# 評分表原意對照(Phase 10 增量 2,2026-09-24)

乾淨代理只讀交接文件業務描述,不看評分表、程式、測試,對一小批情境寫它認為的答案;跟評分表不一致的格列給使用者覆核。代理的答案不當標準答案,評分表沒有改。

- 第 1 批(`rubric-intent-batch1.md`):用生成器第一版的情境,點擊多於曝光、預算在整數上限這類不合理資料很多;代理幾乎每筆都先質疑資料。之後生成器改成照漏斗順序造正數計數(點擊不多於曝光、轉換不多於點擊),評估集換批。
- 第 2 批(`rubric-intent-batch2.md`):換批後的情境,每格 3 筆。

| 評分格 | 評分表答案 | 第 1 批代理 | 第 2 批代理 | 一致 |
|---|---|---|---|---|
| 暫停 | 不值得加 | 3/3 不值得加 | 3/3 不值得加 | 是 |
| 啟用、曝光點擊不全是正數 | 不值得加 | 3/3 證據不足 | 3/3 證據不足 | 否 |
| 啟用、曝光點擊都是正數、轉換營收有正數 | 值得加 | 3/3 證據不足 | 3/3 證據不足 | 否 |
| 啟用、曝光點擊都是正數、轉換營收都不是正數 | 證據不足 | 3/3 證據不足 | 3/3 證據不足 | 是 |

代理的理由歸納(不是評分表的一部分):

- 曝光或點擊是負數、缺值時,它認為是資料異常、判「證據不足」,不是「不值得加」。
- 有轉換或營收時,它還看欄位之間是否自洽(有營收沒轉換、有轉換沒營收、點擊率接近九成、花費低到不合常理),不自洽就判「證據不足」;營收缺值也判「證據不足」。
- 評分表沒有「資料是否自洽」這個概念;生成器第二版只保證計數的漏斗順序,營收與轉換、花費與曝光之間仍可能不自洽。

## 第 3 批(5 格版評分表,2026-09-24)

使用者裁定評分表加「資料自不自洽」、評分格變 5 格後,依計劃重跑一批原意對照(`rubric-intent-batch3.md`)。生成器第三版:正常格照漏斗順序造、沒有負數與缺值;資料異常格輪流造單一故障。每格 3 筆,情境不含負數(這批抽到的異常都是缺值)。

| 評分格 | 評分表答案 | 代理 | 一致 |
|---|---|---|---|
| 暫停 | 不值得加 | 3/3 不值得加 | 是 |
| 資料異常 | 證據不足 | 2/3 證據不足;營收缺值、有點擊沒轉換那筆判「不值得加」 | 部分 |
| 沒投放(點擊是零) | 不值得加 | 3/3 不值得加 | 是 |
| 有價值 | 值得加 | 1/3 值得加;轉換率 88% 那筆判「證據不足」(數字不合理)、轉換零但營收正那筆判「不值得加」 | 否 |
| 沒價值(轉換營收都是零) | 證據不足 | 3/3 不值得加(「有點擊沒轉換就是沒效益」) | 否 |

代理的理由歸納(不是評分表的一部分):

- 「沒價值」格:使用者裁定是「證據不足」;代理三筆都判「不值得加」,理由是有點擊卻沒有任何轉換營收,已經是足夠的負面訊號。這條直接跟使用者本人的裁定不一致。
- 「有價值」格:代理把「轉換零但營收正」讀成沒效益,把轉換率接近九成讀成數字不合理;後者照使用者裁定不判。
- 代理另外把「點擊是零卻有營收」「轉換很多營收是零」「花費極低卻有大量點擊」讀成資料矛盾;這些都不在使用者裁定的「程式判得出的異常」清單裡(評分表只看負數、缺值、點擊多於曝光、轉換多於點擊)。

使用者覆核(2026-09-24,使用者本人,經協調者轉達):「沒價值」格的不一致維持原裁定——有點擊、轉換營收都是零 → 證據不足,不改評分表;理由是一小時窗太短、轉換常有延遲,看不出來不等於沒效益。其餘不一致(轉換率過高、零轉換有營收、代理自己讀出的其他矛盾)照使用者先前「數字合不合理不判」的裁定,紀錄照實列,評分表不改。
