### F3 沒有欄位的 mypy 錯誤被轉換器靜默丟掉(未使用的 type: ignore)

severity: major
blocking: 是——嚴格模式下的真型別錯誤會在有其他錯誤時被漏報,只有它一個時卻被誤報成工具失敗。

- 位置:tools/mypy_sarif.py 的 LINE 規則。引句:「r"^(?P<path>.+?):(?P<line>\d+):(?P<column>\d+): (?P<level>error|warning|note): "」
- 問題:mypy 對某些錯誤不輸出欄位,即使開了 `--show-column-numbers`,例如 `src/x.py:8: error: Unused "type: ignore" comment  [unused-ignore]`(strict 含 warn_unused_ignores)。規則要求欄位,所以整行不符合、被丟掉。
- 重現(用專案設定):在 clone 的 `src/rtb/domain/_checks.py` 把 `import re` 改成 `import re  # type: ignore`,並另加一個 return-value 錯誤,執行 `.venv/bin/python tools/mypy_sarif.py --out /private/tmp/s1r1/o2.sarif`:結束碼 0,SARIF 只有 return-value 一條;而 `python -m mypy` 實際輸出兩個錯誤(`_checks.py:8` 的 unused-ignore 與 `:29` 的 return-value)。
- 單獨只有這一種錯誤時(rc 1、解析不到任何發現):走到 `completed.returncode == 1 and not findings`,回 2 並宣告「mypy 無法產出可用的結果」,是誤報成工具壞掉,不是型別錯誤。
- 建議:欄位設為選填(`(?::(?P<column>\d+))?`,缺欄位時 startColumn 省略或用 1),並加一條測試餵 `a.py:1: error: Unused "type: ignore" comment  [unused-ignore]`。

### F6 SARIF 的 uri 沒有做 URI 編碼,絕對路徑外檔也原樣輸出

severity: minor
blocking: 否——對一般專案路徑無影響,含空白或百分號的檔名才會對不上。

- 其餘 SARIF 檢查通過:version 2.1.0、level 只有 error 與 warning、rules 與 ruleId 一一對應。
