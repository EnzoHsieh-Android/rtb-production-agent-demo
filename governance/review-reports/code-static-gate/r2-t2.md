# r2-t2 審查報告(獨立審查員,針對 r2-snapshot.patch)

檢查範圍:轉換器 `tools/mypy_sarif.py`、`.lumos/lint.json`、CI 接線測試 `tests/test_static_wiring.py`、`ci.yml`。重點三項:空檢查回報乾淨、CI 接線繞過、邊界輸入。純讀碼與推演,未執行實驗;現況檔只用來確認 `pyproject.toml` 與 `ci.yml` 的內容,所有引句取自快照。

## 發現

### F1 範圍解析失敗時,轉換器什麼都沒檢查卻回報乾淨
severity: major
blocking: 是 這是問題(1)的直接成立:設定讀不到或形式不同,mypy 不跑,SARIF 空、結束碼 0,新增型別錯誤全部放行,且沒有任何訊號。

引句:「return list(config.get("tool", {}).get("mypy", {}).get("files", []))」
file: `tools/mypy_sarif.py:83`(快照為 `configured_directories`)

- `[tool.mypy].files` 缺失或被改名時回傳 `[]`,`select_paths` 對任何檔案都回空,轉換器走「全部在範圍外」分支寫空報告。
- mypy 的 `files` 也可以寫成字串(例如 `"src, tools"`);`list("src, tools")` 會變成單一字元清單,同樣什麼都比對不到,靜默乾淨。
- 範圍寫成 `"."`、檔案路徑或 glob 時,`relative == d or relative.startswith(d.rstrip("/") + "/")` 也不會命中(`"."` 會變成 `""` 加 `/`,再變成 `"./"`,相對路徑不會以它開頭)。
- 應該:範圍為空時大聲失敗(結束碼 2);字串要拆成清單;`"."` 要視為全部。
- 測試只覆蓋「有 `src`、`tools` 的正常設定」,沒有守這條。

### F2 「全部在範圍外就零發現」分支對路徑判斷的任何錯誤都是靜默通過
severity: major
blocking: 是 同屬問題(1):提前 `return 0` 的出口沒有任何「這真的是測試檔而不是判斷錯了」的核對。

引句:「if not mypy_args:」
file: `tools/mypy_sarif.py:680`

- 快照中 `select_paths` 對「專案根目錄之外的絕對路徑」直接 `continue`,等於丟掉不檢查、當作乾淨(作者已在現況改為回報失敗,這裡確認方向正確)。
- 同一個出口還吞掉其他丟棄理由:路徑前綴格式若與 `LUMOS_TEMP_PREFIX` 不符(lumos 版本改臨時目錄命名、Windows 反斜線、`./` 開頭),整批被當範圍外。`LUMOS_TEMP_PREFIX` 是寫死的 `^\.lumos/lintbase-[^/]+/(?:base|head)/`,而 `./.lumos/...` 開頭就不匹配。
- 應該:丟掉檔案時,要求被丟掉的每一個都能被正面確認為「範圍外的專案內檔案」,否則失敗。
- 現況的 `partition_paths` 已往這個方向走,但 `./` 前綴是否被涵蓋需另行確認。

### F3 接線測試對 CI 的兩處繞過:多空白的 `|| true` 與 shell 層面的包裹
severity: major
blocking: 是 問題(2):作者宣稱「被 echo、|| true、if: 條件包住」都會被抓,實際仍能繞過,而測試「守衛的守衛」只用最標準寫法驗證。

引句:「if "|| true" in code or "||true" in code:」
file: `tests/test_static_wiring.py:348`

- `python -m mypy ||  true`(兩個空白)、`|| :`、`|| exit 0`、`|| echo ok`、`; true`、`| tee log`(管線吃掉結束碼)都不會被抓。
- `runs_tool` 只檢查前三個字。`python -m mypy --version`、`python -m pytest --collect-only`、`python -m pytest -k nothing`、`python -m ruff --version` 都算「有直接執行」。
- 多行 `run: |` 區塊逐行當指令,因此下面這種寫法會通過,但實際不會執行 mypy。
  - 區塊內第一行 `exit 0`,第二行 `python -m mypy`。
  - 或 `if false; then` 後接 `python -m mypy`。
- 剖析器的 `if:` 偵測只認 YAML 的鍵,看不到 shell 的 `if`。
- 應該:剖析後拒絕含 `||`、`;`、`|`、`exit`、`set +e`、`if`/`then` 的指令行,並要求不帶 `--version`、`--help`、`--collect-only` 等旁路旗標。

### F4 CI 觸發限制的偵測不完整
severity: major
blocking: 是 問題(2):把 `push` 限制成只有 tag 觸發,或用 `on:` 的另一個 `push:` 字樣,就能讓測試通過而 CI 實際上不跑。

引句:「assert "push:" in [line.strip() for line in text.splitlines()]」
file: `tests/test_static_wiring.py:401`

- 只要檔內任何一行剛好是 `push:` 就過;不確認它在 `on:` 之下,也不確認 `push:` 沒有子鍵。`push:\n  tags: [v*]` 只在打標籤時觸發,`ci_problems` 只檢查 `branches`、`paths`,對 `tags`、`tags-ignore` 沒有反應。
- 沒有檢查 `runs-on`、`needs`、`timeout-minutes: 0` 這類讓工作不跑的設定;`branches` 與 `paths` 用子字串比對,`branches-ignore`、`paths-ignore` 恰好被吃到,但任何含 "paths" 字樣的合法指令會誤報。
- 同一份快照把 `pull_request:` 從觸發移除,`from fork` 或 PR 分支上的檢查在 push 之前不存在;作者已在知識筆記記錄,屬有意取捨。

### F5 接線測試改弱了 lumos 端的覆蓋
severity: major
blocking: 是 問題(2):原本「所有設定的分析器都必須接進 lumos」,現在只檢查兩個寫死的工具,新增 bandit/pylint 設定不再被要求接線,和測試宣稱的目的相反。

引句:「for tool in configured_analyzers() & set(LINT_TOOL_PREFIX):」
file: `tests/test_static_wiring.py:420`

- 舊版對 `configured_analyzers()` 全部要求接線;新版與 `LINT_TOOL_PREFIX` 取交集,`[tool.pylint]`、`[tool.bandit]`、`[tool.pyright]` 等出現在 pyproject 時,lumos 端不會要求。CI 端的測試仍會擋,所以只剩「推送前」這一層漏洞。
- 另外只檢查命令以固定前綴開頭,沒檢查 `mypy_sarif` 命令有帶 `--only-configured-paths`、ruff 命令有帶 `--output-file {LINT_SARIF_OUT}`。把 `.venv/bin/ruff check --exit-zero ...` 或拿掉 `--only-configured-paths` 都通過。

### F6 lumos 給的臨時路徑:mypy 與 ruff 是否真的能在那份副本上運作沒有被測到
severity: minor
blocking: 否 屬未驗證的風險,快照的說明稱已用 lumos 自己的判定函式實測,只是測試沒把它固定下來。

引句:「kept = adapter.select_paths(paths, ["src", "tools"])」
file: `tests/tools/test_mypy_sarif.py:551`

- `select_paths` 保留的是原始路徑(含 `.lumos/lintbase-*/head/` 前綴)並傳給 mypy;測試只驗證過濾函式,沒驗證 mypy 在這種孤立副本上能解析同套件的匯入。若無法解析,會在 base 與 head 各出一批 `import-not-found`,路徑不同,可能被當成新增,或全部被同樣抵銷而漏抓。
- ruff 的 `per-file-ignores` 用 `tests/**`;快照又把該項收窄(拿掉 `S110`、`ARG`、`SIM117`)。臨時副本路徑 `.lumos/lintbase-*/head/tests/x.py` 是否還匹配 `tests/**` 沒有測。若不匹配,新增測試檔會被判成新增告警而誤擋。
- 建議加一條用真實 lumos 臨時目錄跑 ruff 與 mypy 的整合測試。

### F7 邊界輸入:被刪除的檔案與二進位/非 UTF-8 輸出
severity: minor
blocking: 否 走的是「工具失敗、大聲報錯」的安全方向,只是造成誤擋而非漏抓。

引句:「completed.returncode == 1 and not findings」
file: `tools/mypy_sarif.py:687`

- `--only-configured-paths` 傳進已刪除的檔案時,mypy 回傳 2,整個閘失敗而不是略過該檔。
- `subprocess.run(..., text=True)` 用系統預設編碼解碼,mypy 輸出含非 UTF-8 檔名時會丟 `UnicodeDecodeError`,是未處理的例外(結束碼 1,不是 2),lumos 看到的是「命令失敗」,方向仍然安全。
- `timeout=600` 逾時會丟 `TimeoutExpired`,同樣不是乾淨的結束碼 2。

- 缺欄位號的錯誤現在預設欄位 1,不再被丟棄。
- URI 百分號編碼與解碼往返成立。
- `ci.yml` 現況實際會執行 ruff、mypy、pytest 三個步驟,沒有條件與吞失敗。
