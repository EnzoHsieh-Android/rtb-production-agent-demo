## 發現 1：「經」的長編號太寬，被自己那個節點往上拉的虛線從中間劃過
severity: minor
blocking: 否
引句：「rise_x = source_x + _edge_start_offset(edge.source) // 2」
引句：「return f"判斷 {own}・經 {entered}"」
file: `src/rtb/demo/flow_svg.py:421`、`src/rtb/demo/flow_svg.py:202`

- **為什麼會這樣**：
  - 跳過同泳道節點的虛線，從起點節點的正中央（x+72）往上拉。
  - 編號字從 x+4 開始畫。短的「判斷 13」只寬大約 45px，碰不到那條線。
  - 本輪加的「判斷 23・經 12」寬 84.5px，一路延伸到 x+88，正好蓋過 x+72 那條垂直線。
  - 所以是 g3（虛線改道）和 g4（加長編號）兩個修正疊在一起才出現的。
  - 反方向也一樣：虛線落進終點節點時，也是從正中央垂直下來，終點若帶長編號同樣會被劃過。
- **例子**：
  - 輸入：真跑 F6，1440 寬，看「領取建議」節點。
  - 預期：編號字完整、沒有線穿過。
  - 實際：「試太多次了（跳過中間 2 個節點）」那條虛線的 path 是 `M 2384 360 L 2384 336 …`。編號外框是 x 2316–2400.5、y 341–356，垂直那一段從「經」和「12」中間穿過（截圖 `1440-F6-skip-over-badge.png`）。
  - 七個情境的連線與文字外框逐一量過，只有這一處相交。在 390 寬的 /report 裡結果一樣。
- **重現**：
  - 開 `/?scenario=F6`，對 `g.is-skip path` 每 2px 取一個點，看有沒有落在 `.decision-badge` 的外框裡。量測腳本是 `/Users/enzo/.playwright-mcp/p12r3/measure.js`。
- **建議**：
  - 垂直線改從節點右側 3/4 處拉。
  - 或者把「・經 N」換行，或改成畫在節點框裡面。
  - 測試裡再加一條斷言：長編號的外框不能碰到跳線的 x。
