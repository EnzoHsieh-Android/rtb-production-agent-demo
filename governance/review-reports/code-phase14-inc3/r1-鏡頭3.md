## 發現 1:`test_runner.py` 的邊界測試名單沒跟著「AI 不匯入」的新政策收緊(有另一份新測試頂住,不會漏防)

severity: minor
blocking: 否

`src/rtb/analyzer/runner.py` 這次改寫的檔頭宣稱:

引句:「這支檔不匯入 AI 決策模組與模型閘道」

(逐字見 `r1-snapshot.patch:1754`;因為這句只在 src 的 docstring 裡,不在 `r1-tests.patch` 本身,以下用
`r1-snapshot.patch` 全量 diff 的行號取代逐字引句,審材外核對一律用 `路徑:行號`。)

但 `tests/analyzer/test_runner.py`(這次沒有出現在 `r1-tests.patch` 的改動清單裡,等於沒跟著這次「AI 退
出決策」收緊)的邊界測試 `test_the_analyzer_runner_uses_only_production_collaborators`
(`tests/analyzer/test_runner.py:94-114`)允許清單仍然把 `"rtb.analyzer.ai_judge"` 與
`"rtb.analyzer.modelgate"` 留在 `rtb_modules <= {...}` 的允許集合裡(第 106-112 行)。實測:把這份允許
集合原樣搬出來,餵一段假設 `runner.py` 又重新 `from rtb.analyzer import ai_judge, modelgate` 的原始碼去
跑同一套 AST 判準:

```
rtb_modules = {"rtb.analyzer.ai_judge", "rtb.analyzer.modelgate", "rtb.analyzer.flow"}
rtb_modules <= allowed  # True —— 這支邊界測試不會抓到 runner.py 重新匯入 AI 決策模組
```

也就是說,如果之後有人不小心把 `ai_judge`/`modelgate` 匯入寫回 `runner.py`,這支「邊界測試」本身**不會
翻紅**,跟 docstring 宣稱的「邊界測試守」不一致——這一支測試的允許清單是孤兒(沒有跟著政策收緊)。

不過**同一次改動裡新增了一支更嚴的守衛**:`tests/test_spawn_boundary.py:614`
(`test_only_phase13_eval_uses_ai_judge_and_runner_stays_rule_only`,屬於 `r1-tests.patch` 本次改動)
用子行程真的 `import rtb.analyzer.runner` 之後檢查 `sys.modules`,斷言
`"rtb.analyzer.ai_judge"`、`"rtb.analyzer.modelgate"`、`"rtb.modelclient"` 都不在載入清單裡。我把
`runner.py` 複製到 `/tmp` 並手動加回 `from rtb.analyzer import ai_judge` 之後在子行程匯入驗證:
`"rtb.analyzer.ai_judge" in sys.modules` 回 `True`,證實這支新測試**真的會**抓到同樣的迴歸(是遞移式的
真匯入檢查,比舊測試的靜態 AST 白名單更嚴)。所以現況是「有兩道防線,一道是孤兒、一道頂用」,不是完全
沒有防護,故降級為 minor、不擋——但建議把 `tests/analyzer/test_runner.py:110` 的允許集合也拿掉這兩個
名字,兩份守衛表達的政策才會一致,免得將來只看這支測試名字的人被誤導。
