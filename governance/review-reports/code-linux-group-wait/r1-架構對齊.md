### 1. 環境掃描新放行的 dict 推導式，繞過了同一支守衛既有的「刪鍵要抓」規則
severity: minor
blocking: 否
引句:「或是逐項走 os.environ.items() 的 dict 推導式(只濾掉幾個鍵」
file: `tests/test_suite_isolation.py:81`

**重現**:在 /tmp 複本用專案 venv 呼叫 `env_offenders` 試了三種寫法:
- `env = {k: v for k, v in os.environ.items() if k != "HOME"}` → `[]`(放行)
- `env = {**os.environ}; del env["HOME"]` → `['probe:3']`(抓到)
- `env={k: "x" for k, v in os.environ.items()}` → `[]`(放行，值全被換掉也不管)

同一支守衛原本的判準是「之後清空或刪鍵的都抓」(`_destroyed_names`)。新分支等於開了第二條放行路徑，卻不套用這條判準：用推導式濾掉 HOME 或 PATH，跟 `del env['HOME']` 效果一樣，結果不一樣。這在架構上是內部判準不一致，可能變成守衛漏洞，影響多大留給正確性席判斷。

**建議**:推導式分支只認兩種形狀:
- 值原樣帶過(`value.value` 是 generator 的值變數);
- 過濾條件只准排除明列的無害鍵，或至少不准排除 `MODEL_ENV`、HOME、PATH。

再把上面兩個放行的例子加進 probe 的「要抓」清單。

### 2. 正式碼改成看 /proc 判斷存活，測試的存活小工具還停在只送訊號、只照顧 macOS
severity: minor
blocking: 否
