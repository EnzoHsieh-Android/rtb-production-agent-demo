### 1. /proc 讀得到但內容不像 Linux 時會判成「沒有活的」,不會退回送訊號(不安全的方向)
severity: major
blocking: 是
引句:「讀不到行程表回 None(交給送訊號判斷)」
引句:「continue  # 讀的當下剛結束:不算」
file: `src/rtb/modelclaude.py:222-242`

- **問題:** 只有 `PROC_ROOT.iterdir()` 丟 OSError 時才回 None。只要 /proc 目錄存在,不管裡面是什麼,結果都是 False。下列情況函式都一律回 False:
  - /proc 是空目錄:FreeBSD 預設就這樣,沒掛 procfs 的 chroot 或沙盒也是。
  - pid 目錄底下沒有 `stat`:FreeBSD 的 procfs、illumos。
  - /proc 屬於另一個 PID 命名空間:例如 `unshare --pid` 沒加 `--mount-proc`,或容器掛了宿主的 /proc,編號對不上。
- **後果:**
  - 文件寫的是「讀不到 /proc 才退回送訊號」,實際上這些平台會在殺整組後只送一次 SIGKILL,確認迴圈直接變成空轉,接著就刪暫存目錄、領回主行程。
  - 卡在 D 狀態的,或殺的瞬間還在 fork 的成員,就不會再補殺,也不會記 error 日誌。
  - 這正是「寧可多等不可漏殺」最怕的方向。原本的 killpg 在這些平台至少還會補殺、逾時也會留日誌。
- **重現:** 在 /tmp 複本跑 `probe_r1.py`,拿本行程**自己還活著的群組**來查:
  - 空 /proc:`False`
  - 只有 `status` 沒有 `stat`:`False`
  - 另一個命名空間(只有 pid 1):`False`
- **建議:** 先做自我檢查。行程表裡找不到 `os.getpid()` 的 stat,或它的 pgrp ≠ `os.getpgrp()`,就回 None 退回 killpg。另外補一支測試:假 /proc 是空的或沒有 stat 時,`_has_live_members` 要退回送訊號判斷。
