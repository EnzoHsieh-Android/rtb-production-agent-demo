## 發現 1:瀏覽器測試另起第二套測試工具鏈,從真家目錄的 npx 快取挑版本,CI 永遠跳過
severity: major
blocking: 是

引句:「sorted(_REAL_HOME.glob(".npm/_npx/*/node_modules"))」
引句:「CI 沒裝,照例跳過,行為的靜態那一半由 test_page 守」

**專案原本的測試做法只有一套:**
- 全部是 Python/pytest,依賴釘死在 `requirements-dev.txt`,只有 pytest、ruff、mypy 等,沒有 node 或 Playwright。
- CI 一條指令全跑:file: `.github/workflows/ci.yml:25`(`python -m pytest -q`)。
- 既有的跳過都是看平台事實或資料在不在,不是看工具鏈有沒有裝。例如 file: `tests/model/test_claude_process.py:254` 看是不是 Linux;file: `tests/demo/test_ai_demo.py:414` 看入庫目錄在不在。
- 以前的瀏覽器驗證都是協調者手動跑 Playwright 截圖,寫在驗收紀錄裡,不算自動測試。

**新測試的做法:**
- 用 subprocess 起 node,把 JS 原始碼包在 Python 字串裡跑。
- node 從真家目錄的 `.nvm` 找,Playwright 模組從 `~/.npm/_npx/<雜湊>/node_modules` 找,瀏覽器從 `~/Library/Caches/ms-playwright` 找。
- 位置:file: `tests/demo/test_flow_popover_browser.py:32`、file: `tests/demo/test_flow_popover_browser.py:58`、file: `tests/demo/test_flow_popover_browser.py:191`。
- 結果是第二種語言執行環境,版本不固定(glob 抓到哪個 npx 快取就用哪個),也沒寫進任何依賴清單。

**造成的後果:**
- 第 2 輪修正裡 p2、p3、p5、s3 的行為守衛只在作者本機生效,CI 恆為跳過。
- test_page 的「靜態那一半」只比對腳本有沒有某段字串(例如 `'const HOVER_CLOSE_DELAY_MS = 300;' in FLOW_SCRIPT`),守不住行為。
- 例子:
  - 輸入:之後有人改了 FLOW_SCRIPT,讓 Esc 不再把焦點還給格子。
  - 預期:CI 紅燈。
  - 實際:CI 綠燈(這支跳過)。只有在裝了 npx Playwright 的機器上才會抓到。
- 驗收紀錄(file: `docs/rtb-production-agent-demo-knowledge/Systems/展示頁面.md:119`)自己也寫了 REVISIT:「否則每次改浮出框腳本都要在本機跑一次那支測試」。

**重現方式:**
1. 在臨時副本用 venv python 跑 `PYTHONPATH=src python -m pytest -rs tests/demo/test_flow_popover_browser.py`。本機結果是 1 passed。
2. 同一支測試模組的 `_node()`、`_playwright_modules()` 在本機挑到的是 `~/.nvm/versions/node/v24.16.0/bin/node` 與 `~/.npm/_npx/e41f203b7505f1fb/node_modules`,是一個隨機雜湊的快取目錄。
3. 在 CI 的 ubuntu 映像上兩者都是 None,一定跳過。

**比較一致的接法:**
- 改用 Python 版 Playwright,釘版本寫進 `requirements-dev.txt`。
- CI 的 checks 工作加一步 `python -m playwright install --with-deps chromium`。
- 測試改成同步 API 直接在 pytest 裡開 file://。不用 node,也不用 JS 字串。
- 這樣跟既有的依賴清單、CI、跑測試的語言是同一套。
- 如果決定不在 CI 跑:至少把工具來源固定成明確設定(環境變數必填,不去掃 npx 快取),並登記成使用者裁定的例外。
