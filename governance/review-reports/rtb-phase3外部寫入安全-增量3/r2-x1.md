### 1. 共用 HTTP 用戶端的標頭白名單無法送出能力憑證
severity: major
blocking: 是 照字面實作時寫入請求會在送出前失敗，或因缺憑證被 DSP 拒收
引句:「帶第 3 步簽好的憑證與冪等鍵送出寫入。呼叫期間不開任何資料庫交易。」
file: `src/rtb/httpclient.py:24`
file: `src/rtb/httpclient.py:56`
file: `src/rtb/capabilitykit.py:25`
file: `tests/httpclient/test_httpclient.py:132`

共用用戶端只允許 `ClientHeader.IDEMPOTENCY_KEY`，傳入字串 `X-Capability` 會丟 `TypeError`；既有測試還把列舉成員鎖死為只有冪等鍵。計劃的落點與合約都沒有要求把能力憑證加入白名單並同步更新鎖死測試。

具體例子：輸入「合法提案、合法 `X-Capability`、合法冪等鍵」→ 預期「共用用戶端送出兩個標頭，DSP 執行寫入」；照現況實作則「能力憑證無法交給 `request_json`，請求在本地失敗」，若省略它則 DSP 回 401。應補一條合約，明確要求白名單恰含冪等鍵與能力憑證，且仍拒絕故障注入等任意標頭。

### 2. 同一輪固定時間會讓過期後的重簽再次簽出已過期憑證
severity: major
blocking: 是 第 2 版新增的過期重送路徑會在正常慢請求下必然轉人工
引句:「時間只有一個來源(呼叫端給這一輪的現在時間,往下傳給檢查、開始一筆、簽發、寫結果)」
file: `src/rtb/executor/capability_signer.py:109`
file: `src/rtb/executor/capability_signer.py:125`

簽發器直接用傳入的 `now` 設定 `iat` 與 `exp = now + 120`。若「一輪的現在時間」是單一固定值，憑證過期後重簽仍會得到相同的到期時間，並非真正重簽。

具體例子：輸入「本輪時間 12:00:00，重讀 DSP 花 121 秒」→ 第一張憑證到期於 12:02:00，送達時已過期；預期「收到過期後，從同一個注入時鐘重新取 12:02:01，簽出新的有效憑證並同鍵重送」；照字面會再次以 12:00:00 簽發，第二張仍已過期，錯誤轉人工為「憑證被拒」。應區分「唯一時鐘來源」與「整輪共用同一個時間值」，並為每次簽發重新讀時鐘。

### 3. 回應對照表漏掉共用用戶端會正常回傳的 3xx
severity: major
blocking: 是 未列入對照的回應會讓嘗試停在嘗試中並永久鎖住廣告
引句:「可重試的 503、其他 5xx、逾時、斷線、回應讀不懂」
file: `src/rtb/httpclient.py:49`
file: `src/rtb/httpclient.py:67`

共用用戶端不跟隨重新導向，但會捕捉 `HTTPError`，解析本文後把 3xx 狀態碼正常回傳。第 2 版的表只涵蓋 200、指定 4xx、5xx 與無法解析的回應；合法 JSON 的 3xx 不屬於任何一列，也沒有條款要求所有整數狀態碼必有去處。

具體例子：輸入「DSP 或前置代理回 `302` 加合法 JSON」→ 預期「不跟隨重新導向，持久化成結果不明並留待同鍵查證」；照字面則回應對照函式沒有結果，嘗試仍是嘗試中，同廣告後續提案全部被跳過，增量 4 也看不到可對帳的結果不明狀態。應增加未識別 HTTP 狀態的兜底轉換及窮舉測試。

### 4. 鎖檔沒有綁定資料庫的唯一身分，路徑別名可同時取得兩把鎖
severity: major
blocking: 是 單一執行者保證可被一般的符號連結路徑繞過，重現本節要防止的吞結果事故
引句:「啟動時對資料庫旁的鎖檔取得不等待的獨佔鎖,拿不到(已有另一個執行迴圈在跑)就以非零代碼結束」

「資料庫旁的鎖檔」若直接由命令列路徑拼出，並不等於資料庫的唯一身分。同一個 SQLite 檔案可以經原路徑與符號連結開啟，卻衍生出兩個不同名稱的鎖檔。

具體例子：輸入「執行者 A 使用 `/data/executor.db`，執行者 B 使用指向同一檔案的 `/data/executor-alias.db`」→ 預期「B 在重啟恢復前取得同一把鎖失敗並非零退出」；照字面可分別鎖住 `executor.db.lock` 與 `executor-alias.db.lock`，兩者都啟動，B 隨後把 A 正在送出的嘗試轉成結果不明。應先把資料庫路徑正規化為同一實體身分再決定鎖目標，並讓 S55 用符號連結別名驗證第二個執行者確實被拒絕。
