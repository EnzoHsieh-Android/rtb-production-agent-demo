## 發現 3:錄製目錄檢查兩頭都有縫——預設目錄永遠過不了,而懸空連結和同批殘留佔位會被放行
severity: minor
blocking: 否

`check_recordings_dir` 對外來檔案夠嚴:
- 子目錄、符號連結、大寫檔名、別批的錄製與佔位全部拒絕。
- 存檔中斷留下的 `.<key>.json.<uuid>.tmp` 也會拒絕。

但實測有三處不符合預期:

(a) `open_gate` 沒給錄製目錄時,預設用專案根的 recordings/model/,而那裡有 README.md。所以對預設目錄做檢查一定被拒,錯誤訊息是「錄製目錄裡有不是錄製檔的東西:README.md」。增量 2 的 runner 如果在即時加錄製時沿用預設目錄,一定啟動不了。

(b) 錄製目錄是懸空的符號連結時,`exists()` 回假,檢查照樣放行。

(c) 同一批中斷後留下的佔位檔會通過檢查。等到真的呼叫那個鍵,才以錄製衝突被拒。docstring 說要避免的「看起來像設定錯誤」,在同一批續錄時仍然會發生。

引句:「    if not folder.exists():」
引句:「- 錄製目錄:沒給就用專案根的 recordings/model/。」

例子(直接呼叫 `mc.check_recordings_dir`):

| 輸入 | 實際結果 |
|---|---|
| `default_recordings_dir()`,批次 b1 | REJECT(README.md) |
| 指向不存在路徑的符號連結 | PASS |
| 目錄裡只有 `rec.claim(<key>.json, "b1")` 留下的佔位,批次 b1 | PASS |

修法建議:

- 預設目錄與「開錄前必須是新目錄」的關係要在閘道或計劃裡講清楚。
