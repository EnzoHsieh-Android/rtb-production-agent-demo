severity: major
blocking: 是 會破壞「保存的鍵是唯一依據」合約，使演算法升版後的舊操作無法對帳
引句:「signed = None if blocked else self._sign(proposal)  # 設定檔壞掉在這裡停機」

`_sign()` 會呼叫 `operation_key(proposal)` 重新計算鍵，而實際重送使用的是 `row.key`。因此憑證內的鍵與 HTTP `Idempotency-Key` 可能不同。

具體例子：資料庫保存舊演算法鍵 `k1-persisted`，部署後同一快照算出 `k2-recomputed` → 預期以 `k1-persisted` 簽憑證並同鍵重送 → 實際憑證綁 `k2-recomputed`、請求標頭仍送 `k1-persisted`，DSP 回 403 `capability_scope_mismatch`，嘗試被錯誤轉成 `escalated/capability_rejected`。最小實驗實際得到 `same: False`。
