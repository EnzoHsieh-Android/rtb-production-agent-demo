## 發現 2:驅動程式跑比較表產生器,子行程環境繞過既有的白名單慣例、改成整包 os.environ 直通

severity: major
blocking: 是

`driver.py` 裡跑驗證器(`run_verifier`)與跑比較表產生器(`run_comparison`)都是同一支檔案裡、緊接著的兩個函式,理應是「同一套」子行程模式,但兩者建構子行程環境的做法完全不同:

引句:「popen = subprocess.Popen(list(command), cwd=PROJECT_ROOT, env=dict(env), text=True」
引句:「self.comparison_command, self.demo_id, self.user_env,」

`run_comparison` 收到的 `env` 參數,呼叫端直接餵 `self.user_env`,而 `self.user_env` 在 `Driver.__init__` 就是 `dict(os.environ)`(伺服器組裝 `Driver` 時也沒有另外收窄,見 `src/rtb/demo/server.py:99` 的 `Driver(base, demo_id, keys, state)`,沒傳 `user_env=`)——等於把整台機器當下的環境變數原封不動丟給 `python -m tools.forgery_comparison` 這個子行程。

這跟專案裡另外兩處既有的「給子行程建環境」慣例都不一樣,兩處都是白名單:

file: `src/rtb/demo/launcher/__init__.py:74`(`def child_env(role, keys, *, user_env, ...)`,同樣是白名單組法,`_MODEL_VARIABLES` 才額外放行)

輸入 → 預期 → 實際:
- 輸入:展示伺服器所在行程的環境變數帶著 `SOME_SECRET_TOKEN=abc123`(操作者機器上常見的情況,例如真的模型金鑰、CI token)。

## 發現 3:`tools/forgery_comparison.py` 另造一套(較弱的)環境清洗,沒有重用 `tools/verify_claims.py` 既有的 `clean_environment()`

severity: major
blocking: 是

`forgery_comparison.py` 的「沒有驗證器」欄,直接子行程跑 pytest 用的環境是自己另寫的 `_environment()`:

引句:「env.pop("PYTHONPATH", None)」

只拿掉 `PYTHONPATH`。但 `tools/verify_claims.py` 自己要跑證據測試時,用的是既有、且有明確安全理由的 `clean_environment()`:

file: `tools/verify_claims.py:52`(`CLEARED_VARIABLES = ("PYTHONPATH", "PYTHONSTARTUP")`)
file: `tools/verify_claims.py:1147`-1153(`def clean_environment()`:除了清掉 `CLEARED_VARIABLES`,還把所有 `PYTEST_` 開頭的變數整批清掉,並強制 `PYTEST_DISABLE_PLUGIN_AUTOLOAD=1`;docstring 寫明原因:「能改測試結果卻不在任何檔案裡的東西先清掉(第 2 輪設計審實測 PYTEST_ADDOPTS 帶 -p 能載入把失敗改成通過的外掛)」)
file: `tools/verify_claims.py:1200`(該函式實際被拿來組 `subprocess.Popen(command, cwd=root, env=clean_environment(), ...)`)

`forgery_comparison.py` 整份檔案的目的就是「同一份造假,比較有沒有機械驗證擋不擋得下」,「沒有驗證器」欄那次 pytest 呼叫,正是最該套用 `verify_claims.py` 已經踩過坑、寫好的 `clean_environment()` 的地方,卻自己重新寫了一個更弱的版本。

輸入 → 預期 → 實際:
- 輸入:跑展示的機器環境裡帶著 `PYTEST_ADDOPTS=-p some_plugin_that_marks_everything_passed`(`verify_claims.py` 的文件明白指出這種外掛存在且會把失敗改成通過)。
- 預期(重用 `clean_environment()` 的既有慣例):`forgery_comparison.py` 的「沒有驗證器」欄跑 pytest 前應該清掉 `PYTEST_ADDOPTS`,結果才反映「這份造假底下,普通跑測試會不會被蓋過去」的真實情況。
- 實際:`_environment()` 只拿掉 `PYTHONPATH`,`PYTEST_ADDOPTS` 原封不動流進 `_run([sys.executable, "-m", "pytest", ...], repo, env, step_timeout)`(`tools/forgery_comparison.py:115-116`),比較表左欄(「沒有驗證器」)的結果可能因為機器上的外掛設定而失真,而這正是這張表存在的意義。

重現:
```
cd <臨時複本>
PYTEST_ADDOPTS="-p no:cacheprovider" python3 -c "
import os
env = dict(os.environ)
env.pop('PYTHONPATH', None)
print('PYTEST_ADDOPTS' in env)   # True——forgery_comparison._environment() 沒清掉它
"
```
(用 `no:cacheprovider` 只是示意用途正常的外掛選項也會被原樣帶過去;真正會讓結果失真的是任何會改判定結果的外掛/選項,`clean_environment()` 對此有專門防護,`_environment()` 沒有。)

3 條,blocking 3。
