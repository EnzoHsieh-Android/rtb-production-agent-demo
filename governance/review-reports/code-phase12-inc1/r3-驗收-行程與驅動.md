**Finding 1:驗證器超時後,驅動程式只殺掉驗證器本身;它另開工作階段起的 pytest 整組變成孤兒**
severity: major
blocking: 是
引句:「VERIFIER_TIMEOUT_SECONDS = 600.0  # 驗證器自己跑 77 支證據測試,本機約 45 秒」
引句:「        return VerifierRun(demo_id, _now(), False, (), (f"驗證器逾時({timeout_seconds:.0f} 秒)",))」
file: `src/rtb/demo/driver.py:913`、`src/rtb/demo/driver.py:921-935`、`tools/verify_claims.py:52`、`tools/verify_claims.py:1198-1205`

- **原因**
  - `run_verifier` 用 `subprocess.run(timeout=600)`。逾時的時候,它只對直接子行程(verify_claims.py)送 SIGKILL。
  - 驗證器是用 `start_new_session=True` 起證據測試的 pytest。這組行程不在驅動程式的行程群組裡,本來要靠驗證器自己的 `killpg` 收掉。
  - 但驗證器自己的總時限是 900 秒,比驅動程式的 600 秒長。所以驅動程式先動手,驗證器來不及收自己的孫行程。
  - 結果:測試真的掛住時,pytest 和它起的 DSP、收件口,父行程都變成 1,繼續跑。這正好是「驗證器掛住」這個要驗的情況。
  - 另外,逾時時 `lines=()`,驗證器在掛住之前印出的內容全部丟掉,沒有原樣記下。
- **重現**
  - 做了一個假驗證器,結構照抄 verify_claims:用 `start_new_session=True` 起孫行程 `sleep(60)`,再用 `communicate(timeout=900)` 等它。
  - `run_verifier(..., 2)` 在 2.01 秒回傳 `passed=False`,原因寫「驗證器逾時(2 秒)」,`lines=()`。
  - 1 秒後查 ps:孫行程 72791 還活著,`PPID=1 PGID=72791`。已經手動 kill 掉。
  - 現有測試 `test_a_verifier_that_hangs_is_recorded_as_not_passed` 用的假驗證器只是單純 sleep,沒有孫行程,所以抓不到。
- **建議**
  - `VERIFIER_TIMEOUT_SECONDS` 要大於 `verify_claims.TIMEOUT_SECONDS`,例如 900 再加 60,讓驗證器自己的 killpg 先動手。
  - 或讓驗證器收到 SIGTERM 時先 killpg 證據測試那一組;驅動程式逾時時先送 SIGTERM、等一下,再送 SIGKILL。
  - 逾時時保留已經讀到的輸出。
  - 補一條測試:假驗證器帶一個另開工作階段的孫行程,逾時後孫行程必須不在。
