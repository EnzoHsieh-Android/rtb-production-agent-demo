## 發現 2:兩份「固定兩位小數金額字串」正則式對負號的處理不一致,且沒有測試釘住
severity: minor
blocking: 否

`dsp_client.py` 與 `domain/metrics.py` 這次各自新增一份「固定兩位小數金額字串」的正則,語意應該是同一個概念,但一個收負數、一個不收:

引句:「_MONEY_PATTERN = re.compile(r"-?\d+\.\d{2}\Z")」

引句:「_FIXED_AMOUNT = re.compile(r"\d+\.\d{2}\Z")」

目前行為是自洽的:`metrics._exact_input`/`receipt_amount` 讓 `_fixed_amount(value)` 命中時直接 `Fraction(Decimal(value))` 回傳,完全跳過 `_is_valid_amount` 的 `value >= 0` 檢查;能維持「負數金額一律 na」這條既有不變量,純粹是因為 `_FIXED_AMOUNT` 恰好沒有 `-?`。已用實際呼叫驗證現況正確:
```
$ PYTHONPATH=src .venv/bin/python -c "
from rtb.domain import metrics as m
print(repr(m.receipt_amount('-5.00')))
print(repr(m.receipt_amount(-5.0)))
"
'na'
'na'
```
但 repo 裡沒有任何測試斷言「固定字串負數金額必須是 na」(`grep -rn "receipt_amount(\"-" tests/` 零命中);兩份正則又長得像是「抄一份改個名字」。往後若有人為了跟 `dsp_client._MONEY_PATTERN` 對齊而幫 `_FIXED_AMOUNT` 補上 `-?`(看起來像無害的一致化重構),會讓固定字串負數金額直接變成合法 Fraction、繞過 `_is_valid_amount` 的非負檢查,悄悄違反「金額算不出值時一律回沒有值,絕不是某個具體負值」的既有假設,而且不會有任何紅燈。屬於「未文件化的內部不一致」,現在無害但缺守門測試,故列為 minor 記錄,不擋這次合入。
