## 發現 4:「固定兩位小數金額」在三處各有一套判法,彼此不一致
severity: minor
blocking: 否

引句:「+_MONEY_PATTERN = re.compile(r"-?\d+\.\d{2}\Z")」
引句:「+_FIXED_AMOUNT = re.compile(r"\d+\.\d{2}\Z")」
引句:「+    if isinstance(value, str) and re.fullmatch(r"-?[0-9]+\.[0-9]{2}", value) is not None:」

三處判法:

| 位置 | 接受負號 | 數字字元 |
|---|---|---|
| dsp_client | 是 | `\d`,含 Unicode 數字 |
| metrics | 否 | `\d`,含 Unicode 數字 |
| nine_rules | 是 | 只收 ASCII `[0-9]` |

實測:
- `'١٢.٣٤'`(阿拉伯-印度數字):dsp_client 收,`receipt_amount` 寫成 `12.34`,`rules.Window` 卻丟 `ValueError`。
- `'-1.00'`:dsp_client 收,metrics 不收(收據寫 na),nine_rules 收。

後續子增量把讀取層結果接進 `rules.Window` 時,讀取層會放過一個領域層會丟例外的值。[S1414] 說「以同一 `Fraction` 精確核對」,但實作是三份規則。建議只留一份,放在 `rtb.domain._checks`,並用 `[0-9]` 或 `re.ASCII`。
