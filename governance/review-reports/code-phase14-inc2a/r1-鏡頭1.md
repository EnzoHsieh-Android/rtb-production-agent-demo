## 發現 3:1d/7d 合計超過 SQLite 整數上限時丟 OverflowError,不是 ValidationRejected(讀取路徑會變 500)
severity: minor
blocking: 否

引句:「"INSERT OR REPLACE INTO metrics VALUES (?, ?, ?, ?, ?, ?, ?)",」

- **原因**:單日計數和金額分各自驗「≤ 2**63−1」,但 `_refresh_windows` 在 Python 裡把七天加總後直接寫入,不再經過 `_figures` 驗值。
- **舊路徑**:7d 窗經 `_write_metrics` → `_figures` 驗值,溢位會變成 ValidationRejected。
- **新路徑**:種子直接炸 OverflowError。
- **讀取路徑也會中**:加總同樣發生在 GET 前的 `_materialize_daily`。OverflowError 不是 DspError,伺服器會回 500 `dsp_error`,而不是 4xx。
- 只有種子能寫出這種值,實害低。

重現:
```
s.seed_daily("c1", [{"impressions": 2**62, "clicks": 1, "conversions": 1, "spend": 1, "revenue": 1}]*7, now=NOW)
→ overflow: OverflowError Python int too large to convert to SQLite INTEGER
```

**建議**:加總後過一次上限檢查,轉成 ValidationRejected;或寫窗時走 `_checked_metric`。

## 發現 4:歷史摘要的「最近 3 日」用 DSP 讀取時鐘算,不是決策 now
severity: minor
blocking: 否

引句:「now = _moment(self._clock()).astimezone(UTC)」

- **差異**:`history_limited` 用 DSP 當下時鐘切 3 日界線。收據端只要看到 `summary`,就直接用它(`src/rtb/analyzer/investigation.py:242-250`),`receipt_payload` 收到的決策 `now` 對歷史查詢不再有作用。
- **舊路徑**:同一份沒帶 summary 的列表,是用決策 `now` 切界線。
- **與計劃的關係**:[S1415] 寫明「領域只以決策 now 判」,並舉「T+3d−60s 讀、T+3d+10s 定案」為例。同一個例子套到歷史端點,兩條路徑的答案不同。

重現:
```

history path : 0
```

- **方向**:只會多判「近期有調整」,也就是偏向證據不足,不會多提案,所以列 minor。
- **建議**:在計劃寫明歷史摘要以讀取時刻為準;或讓摘要改帶切界所需的時間戳,由領域用決策 now 算。
