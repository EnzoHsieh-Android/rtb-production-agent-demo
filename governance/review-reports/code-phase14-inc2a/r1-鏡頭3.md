## 沒有翻紅、值得記一筆的觀察(不計嚴重度,無具體失敗場景)

- `_materialize_daily` 被兩個並行讀同時觸發時:外層判斷「是否落後」在鎖外做,實際搬運值(`newest_row`)在拿到 `BEGIN IMMEDIATE` 之後才重讀,新桶用 `INSERT OR IGNORE`——第二個請求進來會是空操作而不是重複寫兩次,冪等物化本身在併發下是安全的,沒有抓到反例。
- 遷移三支 `_migrate_budget_before` / `_migrate_money_columns` / `_migrate_daily_dates` 都包在同一個 `BEGIN IMMEDIATE … COMMIT` 裡,行程猝死會靠 SQLite 交易回滾整批,沒有半途 schema 的狀態;鎖等待期間別的連線先補完欄位,再進來的連線會在拿到鎖後重讀 `PRAGMA table_info` 而不是用鎖外的舊快照,沒有看到重複遷移或漏遷移。
- `execute()` 寫入路徑本身(`_apply` 多存 `budget_before`)沒有改變交易邊界,`current.budget` 是在同一把寫入鎖內讀的,不會有另一支並行寫入插隊改到「前值」的競態。
