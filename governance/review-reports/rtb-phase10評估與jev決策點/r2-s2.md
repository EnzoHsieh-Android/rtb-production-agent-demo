### F1 「歸不了格」與評分表「缺值算不是正數」定義域是否重疊沒說清楚
severity: blocker
blocking: 是
引句:「歸不了格(欄位缺漏或型別不對)也走現行規則」
說明:快照同時宣稱兩件事——① [S711] 評分表「對每一組輸入(狀態 × 四個計數欄位各為正数、零、負数、缺值、布林)恰好給一類」,是窮舉、無死角;② 路由閘另外還有一個「歸不了格」分支,對「欄位缺漏或型別不對」的輸入直接退回現行規則,不進評分格。這兩件事只要「輸入」指的是同一個東西(判斷點的七欄可信型別實例),就會互相矛盾:如果 [S711] 真的窮舉,任何一個已建構出來的判斷點實例(狀態、四個計數欄位不管是正數/零/負数/缺值/布林哪一種)理論上都能歸進 4 格之一,不該存在第三種「歸不了格」的輸入;如果「歸不了格」真能發生,就代表 [S711] 的窮舉宣稱不成立。

   - 具體例(讀法 B,判斷點的欄位不允許 `None`,只能是決策函式已經確認過的合法數字):那「歸不了格」只可能在型別建構「之前」發生,這時 [S711] 的窮舉宣稱其實只涵蓋「已經進得了判斷點的輸入」,並不是路由閘實際會看到的全部輸入空間,快照卻沒有標明這個範圍差異,讀者容易誤以為路由閘也窮舉。
   建議改法:在增量 1 明講判斷點型別的每個欄位是否允許 `None`(即「缺值」在型別層怎麼表示),並且明講「歸不了格」到底是型別建構失敗(判斷點根本組不出來,發生在路由閘之前)還是評分格分類失敗(判斷點已組好但分不進 4 格之一);若後者根本不可能發生(因為 [S711] 窮舉),就應該把「歸不了格(欄位缺漏或型別不對)」這句改寫成「判斷點無法建構」,並移到路由閘呼叫之前的段落,不要跟「歸格」寫在同一句造成兩套語意疊在一起。

### F3 [S711] 的窮舉列舉沒涵蓋狀態值域外的值與 NaN/無限大/超過整數上限
severity: major
blocking: 是
引句:「評分表應對每一組輸入(狀態 × 四個計數欄位各為正数、零、負数、缺值、布林)恰好給一類」
說明:這條合約宣稱「每一組輸入」都恰好落一類,但它列出的類別只有「正數、零、負數、缺值、布林」五種,沒有列到:①NaN、②無限大(`float('inf')`)、③超過資料庫整數上限(`MAX_INT`)這三種在 `is_plain_number` / DSP 白名單裡明確存在、需要特別處理的數值型態,也沒有講「狀態」欄位的值域是不是就只有 `active`/`paused` 兩種、還是任何字串都算合法輸入。
   - NaN:`is_plain_number(float('nan'))` 為真(`isinstance` 通過、不是布林),而 `快照定義的「正數」= is_plain_number 且 > 0`;`nan > 0` 在 Python 恆為 `False`,所以 NaN 剛好會落進「不是正數」那一類——這點沒問題,但快照完全沒寫這個推導,讀者無法從文字判斷 NaN 被歸類到哪裡,只能自己重算。
   - 無限大:同樣是 `is_plain_number` 為真,但 `float('inf') > 0` 為 `True`,會被歸類成「正數」。營收(revenue)在生產環境經 `dsp_client._is_finite_or_none` 明確擋掉無限大(`math.isfinite` 檢查),但評估套件的情境生成器「只依評分格定義與欄位型別造數字,不讀決策函式與測試」,並不保證會重現這條 DSP 層的有限性檢查;若生成器造出 `revenue = float('inf')`,評分表會把它判成「正數」進而落入「值得加」格,這跟生產環境的資料保證(絕對不會有無限大營收)不一致,且評分表文字完全沒提示過這個邊角。
   - 超過整數上限:曝光/點擊/轉換在生產環境經 `_is_count_or_none` 保證 `abs(value) <= MAX_INT`,但評估套件自己造數字時若不主動比照這條上限,理論上能造出超界整數,`is_plain_number` 對超界 Python `int` 一樣回真(Python int 沒有上限),仍會被判成「正數」而不會被特別標記,跟「超過整數上限」這個在 DSP 白名單裡特別處理過的類別脫節。
   - 狀態值域:評分表只寫「暫停中」與「啟用中」兩種,`CAMPAIGN_STATUSES = frozenset({"active", "paused"})` 是 DSP 端的白名單,但快照沒有講判斷點型別的「狀態」欄位本身是不是也限定只能是這兩個字面值(例如用列舉型別在建構式擋掉其他字串)。如果沒有限定,情境生成器造出第三種狀態字串(或 `None`)時,評分表 4 格都套不上,S711 的「恰好一類」宣稱就不成立。
   建議改法:①在「正數」定義那句明寫 NaN、無限大、超界整數各自的分類結果(不要留給讀者重算);②情境生成器的欄位型別描述要求比照 dsp_client 的有限性與上限檢查,或明講評估套件刻意不做這層檢查、超界值一律先被路由閘擋成「歸不了格」(但這又要先解決 F1);③把「狀態」欄位在判斷點型別裡限定成 `{"active", "paused"}` 的封閉列舉,並在 [S711] 的窮舉列舉裡加回這一項,或明寫依據是型別已經在建構式擋掉其他值。

### F4 「每格最少 73 筆」對門檻 0.80 的「值得加」格過度取樣,推導邏輯沒分開講
severity: minor
blocking: 否
