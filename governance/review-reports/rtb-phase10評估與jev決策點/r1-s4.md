### F2 三類評分標準對「有曝光沒點擊」「有轉換沒點擊」等組合沒有歸類,切片與評分會落空
severity: major
blocking: 是
引句:「不值得加:廣告暫停中;或沒有曝光、沒有點擊」

說明:三類條件實質上都以「有曝光**且**有點擊」這個合取式為分界(「值得加」「證據不足」都明寫「有曝光有點擊」),但「不值得加」用頓號「沒有曝光、沒有點擊」——如果讀成「兩者都沒有」(AND),那麼「有曝光但零點擊」(`file:src/rtb/domain/metrics.py:116-121` 的 `cvr()` 註解本身承認「轉換可以多於點擊(例如瀏覽後轉換)」,也就是承認「有曝光/有轉換但零點擊」是業務上合法且會發生的狀態)這種輸入:不滿足「值得加」(缺點擊)、不滿足「證據不足」(缺點擊)、也不滿足「不值得加」的 AND 讀法(曝光不是沒有)——三類都落空,標準答案代理標註員必須自己發明第四種判斷,S706 釘住的雜湊只固定了「發明出來的那個答案」,不代表規則正確。若讀成「兩者任一沒有」(OR),則「有曝光沒點擊」歸「不值得加」,但這樣「有轉換沒點擊」(有點擊為 0、但有真轉換)也被歸類為「不值得加」,與現行規則 `has_delivery` 的語意(只看曝光點擊,不看轉換)不衝突,但與「值得加」定義裡「有曝光有點擊而且有轉換或營收」的精神(轉換代表真的有價值)矛盾——這時「有真轉換卻判不值得加」正是計劃自己想抓的「總平均蓋掉的危險錯誤」那類案例,若標準答案本身把它劃為「不值得加」,受評的候選會被反向懲罰。

具體例:輸入 = 啟用中、曝光 100、點擊 0、轉換 3、營收 50 → 期望類別不確定(AND 讀法:三類都不屬於,測試寫不出斷言;OR 讀法:判「不值得加」,但這廣告明明有轉換有營收)。

建議改法:把「有曝光有點擊」拆成四個獨立布林維度(有曝光、有點擊)寫成 2×2 窮舉表,逐格指定歸類,不要用「有 A 有 B」/「沒有 A、沒有 B」這種容易兩讀的頓號句式。

### F3「有轉換或營收」未排除負值與缺值(None),標準答案生成時行為未定義
severity: major
blocking: 是
引句:「值得加:廣告啟用中、有曝光有點擊、而且有轉換或營收」

說明:`file:src/rtb/analyzer/dsp_client.py:79-81` 的 `_is_finite_or_none`(給 revenue 用)只檢查有限數,不檢查非負;`_is_count_or_none`(給 conversions 用,`file:src/rtb/analyzer/dsp_client.py:76-78`)只檢查 `abs(value) <= MAX_INT`,同樣沒有排除負數。也就是說「營收 = -50」(退款/回沖)、「轉換 = -1」都是能通過 DSP 白名單、合法進入 `decide()` 的證據。評分標準「有轉換或營收」若照字面實作成「conversions != 0 or revenue != 0」或「conversions/revenue is not None」,負的營收、負的轉換都會被判成「有」,进而落入「值得加」——一個實際在虧錢退款的廣告會被標準答案標成「該加預算」。另外「零轉換零營收」(證據不足類)用的是「零」這個詞,但 conversions/revenue 也可能是 `None`(欄位缺漏,語意是「不知道」而不是「已知為零」,`file:src/rtb/domain/metrics.py:83-90` 的 `_checked()` 明確區分 MISSING_DATA 與已知的 0);计划三類定义完全没提到 None 这个第三种取值该落哪一类。

具體例:輸入 = 啟用中、曝光 100、點擊 10、轉換 None、營收 0 → 「零轉換零營收」字面上不成立(轉換不是「零」,是不知道),但業務上顯然也該算「證據不足」;字面實作可能因為 conversions 不等於 0 判定失敗、掉到「值得加」或直接無法分類。

建議改法:評分標準明文寫「有轉換」定義為 `conversions is not None and conversions > 0`(而非 `!= 0`),「有營收」同樣要求 `> 0`;並把 conversions/revenue 為 `None` 的組合明寫進三類之一(通常應等同「零」,歸「證據不足」),不要留給代理標註員臨場判斷。

### F4 切片內正類樣本結構性為 0 時,精確率公式在報告與門檻裡沒有定義怎麼算
severity: major
blocking: 是
引句:「某片的精確率 ≥ 0.95 且召回率 ≥ 0.80,且樣本數 ≥ 30,這片才算「驗證過」」

說明:切片鍵之一是「廣告狀態(啟用/暫停)」,而評分標準規定「不值得加:廣告暫停中」——也就是說「暫停」這個切片的標準答案 100% 是「不值得加」,不可能出現「值得加」的正類樣本。主指標「提案加預算」的精確率定義是 TP/(TP+FP):在「暫停」切片裡 TP 恆為 0(沒有真正該加的樣本),所以精確率要嘛是 0/0(候選一次都沒誤判成「值得加」)要嘛是 0(候選誤判了)。同樣的情況也會發生在「沒有曝光、沒有點擊」這個子切片。[S707]/[S708] 只講「樣本數不足要標未驗證」,完全沒講「正類樣本數為 0 但總樣本數 ≥ 30」這種情況精確率該怎麼寫、算不算「達標」——0/0 沒有明確定義為「視同通過」還是「視同無法驗證」,兩種寫法會讓 `test_a_slice_is_validated_only_when_every_bar_is_met` 這條測試在暫停片上寫出完全相反的斷言,而且都能自圓其說。

具體例:輸入 = 「暫停」切片,30 個樣本,候選對全部 30 筆都正確答「不值得加」→ TP=0, FP=0,精確率 0/0;S708 沒說這算不算「這片精確率 ≥ 0.95」。

建議改法:對正類結構性為空的切片,明文規定改用「不值得加/證據不足」的整體正確率(而不是「提案」精確率)當該片的品質指標,或明講「正類樣本數為 0 的片不適用精確率門檻,改用準確率門檻並在報告加註原因」。
