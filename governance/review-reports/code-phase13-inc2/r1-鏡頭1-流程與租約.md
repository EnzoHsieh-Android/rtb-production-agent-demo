## 發現 1:續租時碰到「不是鎖競爭」的資料庫錯誤，工作會被永久轉成 FAILED，沒開 AI 時同樣的錯卻只是重試
severity: minor
blocking: 否

引句:「except Exception as exc:  # 對已到手的證據做純計算的那一半出錯:同決策丟例外,轉 FAILED」
引句:「rounds = tuple(record for _seq, record in store.investigation_rounds(row.task_id))」

問題出在 `_from_ai` 的 try 範圍太大。這個 try 同時包住兩段:
- 讀資料庫(`store.investigation_rounds`)。
- AI 決策函式裡面呼叫的續租回呼。續租走 `renew_lease`,它只接 `DatabaseBusy`。

所以資料庫層的非鎖競爭錯誤(`sqlite3.OperationalError` 的磁碟 I/O 錯誤、唯讀錯誤等)會被通用的 `except Exception` 接住，寫成永久 FAILED。

沒開 AI 時，同一類錯誤會穿出 `_from_analyzing`,這一步不寫入，下一輪重試。flow.py 檔頭也寫明，只有決策丟例外或歷史資料毀損才轉 FAILED。

計劃 R3-2 本身就警告過「等鎖逾時會穿出去…轉成永久 FAILED」。目前只修了鎖競爭這一種，其他暫時性的資料庫錯誤照樣走進這條路。

- file: `src/rtb/analyzer/flow.py:375-383`
- file: `src/rtb/analyzer/task_store.py:870-883`

例子:
- 輸入：任務停在 ANALYZING,開 `--ai-judge`,續租時資料庫丟 `sqlite3.OperationalError("disk I/O error")`。
- 預期：這一步不寫入、放掉租約，下一輪重試(跟沒開 AI 一致)。
- 實際：狀態列寫成 `failed`,error_detail 是 `OperationalError('disk I/O error')`,這件工作永遠不再推進。

重現:
- 在 /tmp 複本裡，把 `store.renew_lease` 換成直接丟上面那個錯誤的函式。
- 讓假 Judge 呼叫 `ctx.renew()`,再執行 `flow.advance(..., ai_decide=judge, clock=...)`,結果回 `failed`。
- 對照組：把 `store.evidence_for` 換成丟同樣的錯誤，走沒開 AI 的路徑。這時 advance 把例外往外丟，狀態留在 `analyzing`。

觸發條件少見，所以列 minor。

## 發現 2:續租「等鎖逾時」這個分支沒有測試，變異拿掉它也全綠
severity: minor
blocking: 否

引句:「monkeypatch.setattr(store, "renew_lease", lambda _lease, _clock: None)」
引句:「        except DatabaseBusy:」

[S1152] 的測試直接把 `renew_lease` 換成回 None 的函式，所以 `renew_lease` 裡「接住 `DatabaseBusy` 回 None」那段從來沒被執行過。

變異實驗：把 `except DatabaseBusy:` 改成 `except ZeroDivisionError:`,也就是等鎖逾時會直接穿出去。跑流程、租約、runner、AI 決策、啟動器這幾組測試，共 224 條全綠，這個變異沒被抓到。

一旦有人改壞這一段，就會回到 R3-2 要防的情況:等鎖逾時穿出去，被當成決策丟例外，工作轉成永久 FAILED。

- file: `src/rtb/analyzer/task_store.py:880`
- file: `tests/analyzer/test_investigation_flow.py:168`

例子:
- 輸入：續租時另一條連線握著寫入鎖，超過等鎖秒數。
- 預期：有一條測試真的讓鎖競爭發生，而且守住「回 None → RenewalSkipped → 不轉 FAILED」。
- 實際：沒有這樣的測試。

我另外用真鎖做了時序實驗，確認現在的程式行為是對的:
- 設定:TaskStore 等鎖 0.3 秒；另一條連線拿著 BEGIN IMMEDIATE,0.5 秒後才放。
- 結果：續租回 None,模型呼叫 0 次，狀態停在 `analyzing`。
- 租約列依序是取得 w1、放掉。放掉用的是舊收據，因為續租沒成功。

所以這一條只是缺測試，不是現在的程式有錯。建議補一條真鎖版本的測試。
