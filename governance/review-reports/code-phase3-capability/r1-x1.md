### 1. 政策版本通過驗證後被丟棄，無法稽核實際使用的政策
severity: major
blocking: 是 破壞增量 2「政策版本只記不驗、供稽核使用」的設計；成功寫入後無法證明實際憑證使用哪個政策版本
引句:「policy_version: str  # DSP 不懂政策:只記不驗」

`verified_claims()` 會解析 `policy_version`，但 `_authorized_write()` 只把請求內容組成 `Operation`，隨後便丟棄全部憑證聲明。`operations` 資料表、`Operation`、`OperationResult` 與查詢回應都沒有政策版本。

file: `docs/rtb-production-agent-demo-knowledge/Projects/RTB_Phase3外部寫入安全_計劃.md:158`

具體重現：

- 輸入：合法且完全匹配的憑證，`policy_version="audit-v99"`。
- 實際：驗證結果仍有 `audit-v99`，但後續所有可持久化結構都沒有此欄位。
- 預期：成功操作的稽核紀錄應保存實際憑證中的政策版本。

實際輸出：

```text
verified policy_version: audit-v99
Operation fields: ('campaign_id', 'action', 'params', 'expected_version', 'idempotency_key')
OperationResult fields: ('operation_id', 'campaign_id', 'action', 'version_after', 'committed_at', 'replayed')
schema contains policy_version: False
```

這也使本地提案快照無法補救：若簽發器錯簽了另一個政策版本，DSP 端沒有實際收到版本的獨立紀錄可供比對。

### 2. 合法大小內的畸形設定會逸出 ValueError，而不是受控拒絕簽發
severity: major
blocking: 是 直接違反 S29「設定格式不對時拒絕簽發」；外部設定可讓執行行程落入未分類例外
引句:「except (UnicodeDecodeError, json.JSONDecodeError) as exc:」

`_parse_tenants()` 只攔截兩種解析例外。Python 解析超長整數時會因整數字串限制拋出 `ValueError`；5000 位數的內容遠低於設定檔 64KB 上限，所以確實可達。

- 輸入：`max_budget` 是 5000 位數整數的 JSON 設定檔。
