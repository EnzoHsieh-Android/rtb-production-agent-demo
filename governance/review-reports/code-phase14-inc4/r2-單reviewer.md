## 發現 1:誘導雙胞胎缺錄製,仍被算成「一邊沒有有效答案(格式失敗等)」

severity: minor
blocking: 否
引句:「f"  - 一邊沒有有效答案:{one_side} 組(格式失敗等,不代表被名稱帶偏)",」

本輪原則是「缺錄製另列,不算無有效答案」。逐格與合計都照做了,但 `_flips` / `_twin_split` 沒有跟著改。

- 誘導側找不到錄製時,`ai_raw` 是 None,於是被算進翻轉組,落在「一邊沒有有效答案(格式失敗等)」那一行。
- 明細標成「無有效答案(缺錄製)」,自己跟上面的原則矛盾。
- `raw_missing` 只數名稱正常的筆,所以只缺誘導側時,開頭的「⚠ 錄製不全」與摘要的「不可採信」都不會出現。摘要照樣印「另 1 組是一邊沒有有效答案」。
- 只有雜湊說明那一行和不採用理由寫了不可採信,讀者看到的東西前後不一致。

現行入庫錄製缺 0 筆,所以對外數字不受影響;這是產生器對未來錄製不全時的揭露漏洞。

重現:在 `tests/eval` 的 Oracle 上包一層,讓 `anomaly-0` 的誘導側丟 `core.NoRecording`,然後 `build_report` 加 `render`。輸出如下:
- 摘要:「兩邊都有有效答案而結論不同 0 組,另 1 組是一邊沒有有效答案」
- 切片:「一邊沒有有效答案:1 組(格式失敗等…)」
- 明細:「誘導 無有效答案(缺錄製)」

腳本在 scratchpad 的 `r2/twinmiss.py`。

建議:翻轉計數排除任一側 `missing` 的組,另列「缺錄製 N 組」;開頭的錄製不全判斷改看 `report.missing_recordings`(含誘導側)。
