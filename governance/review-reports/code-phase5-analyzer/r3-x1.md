### 1. 多個工作者同時升級舊資料庫時會因重複補欄而啟動失敗
severity: major
blocking: 是 Phase 5 部署到舊資料庫時，並行啟動的分析工作者可能直接崩潰
引句:「if "operation_key" not in columns:」

`PRAGMA table_info(tasks)` 在取得寫入鎖之前執行，拿到 `BEGIN IMMEDIATE` 後沒有重新檢查欄位。兩個 `TaskStore` 同時開啟舊資料庫時，可以都先看見 `operation_key` 不存在；第一個連線完成 `ALTER TABLE` 後，第二個取得鎖仍照舊執行相同指令，得到未被轉成 `TaskStoreBusy` 的 `sqlite3.OperationalError`。

具體例子：兩個分析工作者同時開啟 Phase 5 前的資料庫 → 預期兩者都成功完成遷移，或後取得鎖者重查後略過 → 實際以兩條共享記憶體 SQLite 連線重現，輸出為 `A ok`，接著 `B OperationalError duplicate column name: operation_key`。現有遷移測試只依序開啟單一 `TaskStore`，守不到這個啟動競態。應在 `immediate_transaction` 取得鎖後重新跑一次欄位檢查，再決定是否執行 `ALTER TABLE`。
