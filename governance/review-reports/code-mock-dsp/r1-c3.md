severity: major

# r1-c3 邊界與輸入

實驗方式:在 /private/tmp/c3 起 `python -m rtb.dsp.server --db d.db --fault-injection`,用 curl 與原始 socket 送請求(腳本 /private/tmp/c3/raw.py、raw2.py)。

## Findings

### F1 非數字或負的 Content-Length 讓連線被無聲關閉,不回 JSON
severity: major
blocking: 是 任何客戶端(含 agent)送出壞 Content-Length 就收到空回應,型別化錯誤契約失效,呼叫端無法分辨「可重試」與「永久拒絕」。

- 檔案:server.py `_read_json`,file: `src/rtb/dsp/server.py:111`
- 引句:「length = int(self.headers.get("Content-Length") or 0)」
- 問題:`int("abc")` 丟 ValueError;`Content-Length: -5` 通過 `> MAX_BODY_BYTES` 檢查後,`rfile.read(-5)` 也丟 ValueError。`_dispatch` 只接 RequestRejected、DspError、_NoResponse(file: `src/rtb/dsp/server.py:85`),這兩個例外一路冒出去,被 `handle_error` 吞掉,連線直接關。
- 重現:
  - `curl -sS -i -m 5 -X POST localhost:$P/campaigns/c1/pause -H 'Idempotency-Key: h2' -H 'Content-Length: abc'`
  - 輸出:`curl: (52) Empty reply from server`
  - 同樣 `-H 'Content-Length: -5' -d '{}'` 也是 `Empty reply from server`。
- 補充:`handle_error` 覆寫成 pass,伺服器 stderr 也完全沒有痕跡,排查時看不出發生過什麼。
- 建議:解析 Content-Length 包 try/except,非數字或負數回 400;在 `_dispatch` 加兜底 `except Exception` 回 500 JSON。

### F2 超出 SQLite 64 位元上限的 new_budget 造成 OverflowError,連線無聲關閉
severity: major
blocking: 是 `_validate` 放行任意大的正整數,交易內才炸,結果是空回應而非 422。

- 檔案:store.py `_validate` 只檢查 `isinstance int` 與 `> 0`,無上界;寫入在 `_apply`,file: `src/rtb/dsp/store.py:187`
- 引句:「(updated.budget, updated.status, updated.version, updated.id),」
- 走法:`new_budget=9223372036854775808`(2^63)通過 `_validate` -> BEGIN IMMEDIATE -> `_apply` 綁參數時 sqlite3 丟 OverflowError -> ROLLBACK 後重新丟出 -> 不是 DspError -> 連線無聲關閉。
- 重現:
  - `curl -sS -i -m 5 -X POST localhost:$P/campaigns/c1/budget -H 'Idempotency-Key: h1' -d '{"new_budget":9223372036854775808,"expected_version":4}'`
  - 輸出:`curl: (52) Empty reply from server`
  - 對照:`new_budget=9223372036854775807` 回 200,預算被設成 2^63-1(可接受,但也說明上界只是碰巧由 SQLite 擋)。
- 狀態面:交易有回滾,`GET /operations/h1` 回 operation_not_found,資料未壞,問題只在回應面。
- 建議:`_validate` 明訂預算上界並回 ValidationRejected;同時補 F1 的兜底。

### F3 expected_version 未驗型別,布林與浮點會因 Python 相等而通過樂觀鎖
severity: minor
blocking: 否 只放寬了樂觀鎖的型別嚴格度,資料不會壞,但語意與冪等指紋不一致。

- 檔案:file: `src/rtb/dsp/server.py:151`
- 引句:「return Operation(campaign_id, action, params, body.get("expected_version", 0), key)」
- 走法:`expected_version` 原樣塞進 Operation,`current.version != op.expected_version` 用 Python 比較,`True == 1`、`2.0 == 2`。
- 重現:
  - 新廣告 c2 版本 1:`curl -X POST .../campaigns/c2/budget -H 'Idempotency-Key: t1' -d '{"new_budget":50,"expected_version":true}'` 回 200,version_after 2。
  - 同鍵改送整數 1:`{"new_budget":50,"expected_version":1}` 回 `idempotency_conflict`(指紋把 true 與 1 視為不同)。
  - c1 版本 2 時送 `"expected_version":2.0` 回 200 並升版。
  - 字串 "3"、陣列 [3]、NaN、1e999 都回 409 version_conflict(而非 422),行為不一致。
- 建議:expected_version 必須是非布林整數,否則 ValidationRejected。

### F4 缺 expected_version 預設為 0,回誤導的 409;pause 無本文也一律 409
severity: minor
blocking: 否 缺必填欄位應是驗證錯誤,現況給的是「版本衝突」,呼叫端會誤以為提案過期而去重讀。

- 走法:廣告種子版本為 1,所以 0 永不相符。`POST .../budget` 本文 `{"new_budget":8}` 得 `version_conflict`;`POST .../pause` 無本文亦然(已實測,皆 409)。錯誤代碼沒有指出「缺欄位」。
- 對照:缺 new_budget 則正確回 422 validation_rejected。
- 建議:缺 expected_version 回 422。

### F5 基底類別產生的非 JSON 錯誤回應與未讀取的本文
severity: minor
blocking: 否 只在 HTTP 層偏離「一律 JSON 錯誤」的慣例,內部呼叫端多半只看狀態碼。

- 實測回 text/html 的情形:PUT/DELETE/HEAD(501)、亂碼請求行(400)、過長路徑(414)、過長標頭(431,含 100KB 的 Idempotency-Key)。
- Transfer-Encoding: chunked 的 POST 本文被完全忽略(視為 `{}`),`pause` 因而回 409 而非 400 或 411。
- 建議:覆寫 `send_error` 回 JSON;拒絕 Transfer-Encoding。

### F6 Content-Length 大於實際本文時,處理執行緒無限期卡在 rfile.read
severity: minor
blocking: 否 僅限 127.0.0.1 的測試替身,但單一請求即可永久佔用一條執行緒。

- 檔案:file: `src/rtb/dsp/server.py:115`
- 引句:「body = json.loads(self.rfile.read(length) or b"{}")」
- 重現:送 `Content-Length: 1000` 但只送 16 位元組,4 秒內沒有任何回應(TimeoutError),伺服器未設 socket timeout,執行緒等到客戶端斷線為止。
- 建議:設 `timeout` 類別屬性。

### F7 冪等鍵與標頭處理無長度或字元限制,重複標頭取第一個
severity: minor
blocking: 否 屬設計未明訂的邊界,目前無資料損壞。

- 空白鍵回 400 missing_idempotency_key(正確);標頭名大小寫不敏感(正確)。
- 非 ASCII 位元組的鍵被接受並寫進資料庫(實測 `Idempotency-Key: é` 回 200)。
- 重複 `Idempotency-Key` 標頭只採第一個(`headers.get`),第二個被默默忽略;重複 `X-Fault` 同理。
- 長度上限只靠標準庫的 64KB 標頭行限制,超過回 HTML 431。
- 建議:鍵限制長度與字元集,重複標頭回 400。

## 已驗證無問題

- 本文不是 JSON、是陣列、`{}`、字串/浮點/布林/null 的 new_budget:皆回 400 或 422 的 JSON。
- 本文超過 64KB:回 413 JSON(在讀本文之前擋下)。
- 路徑:尾斜線、大寫(C1 視為不同廣告)、百分比編碼(不解碼,回 404)、查詢字串(被剝除,可用)行為一致且皆為 JSON 404,無例外。
- 預算 2^63-1 可寫入;POST 無本文對 pause 走預設 `{}`,不會崩潰。
- 未知 X-Fault、旗標關閉時的 X-Fault:回 400 JSON。
