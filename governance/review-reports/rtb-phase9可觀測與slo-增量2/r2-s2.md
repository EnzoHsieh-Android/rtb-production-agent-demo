### 5. 多項比率型指標沒有依本節自己宣告的規則寫明零樣本行為,分母為 0 時算不出來或給出誤導性的 0

說明:這是整個「指標清單」小節開頭對自己的要求。實際只有「任務結果率」(分母為 0 時回「無樣本」)與「延遲」大類(樣本數為 0 時回「無樣本」)明確重申零樣本行為;重投率、DSP 呼叫依結果類別的比率、版本衝突率這幾項是「分子/分母」型比率,卻沒有任何一項重申零樣本的處理方式,違反了小節自己開頭立下的規則。

具體例子:一個 24 小時查詢窗內系統完全沒有任何「作廢」類 DSP 呼叫(這在正常運作、沒有觸發對帳作廢流程的期間很常見)。依 [S634] 的定義,DSP 呼叫依結果類別的比率「分母是同一呼叫類別的窗內呼叫數」——這裡呼叫類別「作廢」的窗內呼叫數是 0。
- 若實作直接算 `分子 / 分母` → Python 除以 0 會丟 `ZeroDivisionError`,而 [S630] 要求「指標模組應從事件與紀錄算出清單上每一項指標」是一次算出整份清單,若批次計算沒有個別欄位的例外隔離,這一個 0 樣本的呼叫類別會讓整次查詢(所有其他健康指標)一起失敗。
- 若實作把這種情況吞掉回傳 0% → 會跟「作廢呼叫全部成功」的 0% 錯誤率混在一起,對照的是「延遲」與「任務結果率」都特別要求回「無樣本」而不是 0,同一份規格對同類問題給了不一致的處理標準。
