## 新發現

### 1. 粗體收尾在全形標點後面,後面又直接接文字,GitHub 不會渲染粗體,會露出星號。r2 把開場那句也改成這個寫法

severity: major
blocking: 是
引句:「**這個 Demo 不假設 AI 應該擁有決策權；AI 要保有任何一項決策權，都得由評估與可驗證的證據支持，評估沒過就撤掉。**這是以廣告預算調整為情境的 agent 工作流程。」

查證 file:`README.md:3`(開場)、`README.md:5-8`(四條重點)、`README.md` 正式決策規則三條(snapshot 的 +98 到 +100 行)。實測方式:把同樣寫法丟進 GitHub 的 markdown 渲染(`gh api markdown`,mode=gfm)。`**撤掉。**這是` 輸出成 `<p>**撤掉。**這是</p>`,`- **取得。**AI 即時` 也一樣原樣吐出星號。改成 `**撤掉**。這是` 或 `**取得。** AI` 才會正確渲染成 `<strong>`。

問題:
- 這不是事實錯誤,超出本席範圍,但它是 blocking 級的呈現缺陷。依 CommonMark 規則,收尾的 `**` 前面是標點(。),後面又緊接文字,就不算收尾。
- 結果是 README 第一行,加上四條重點、三條決策規則,在 GitHub 上都會露出 `**`。
- 舊版開場那句獨立成段、`**` 在行尾,原本渲染正常。r2 為了照架構席「併回介紹段首句」把它接上正文,才新壞掉。決策規則三條原本用「：**」收尾,本來就壞,這輪改成「。**」仍然是壞的。

建議改法:所有「標點**文字」一律改成「**文字**標點」,把句號、冒號移到粗體外面。例如 `**……評估沒過就撤掉**。這是……`、`- **決策權要靠證據取得**。AI 即時……`、`- **規則依序看九件事**:暫停……`。改完用 `gh api markdown` 或 GitHub 預覽確認。

### 2. 「確認注入真的發生」比驗證器實際做的強

severity: minor
blocking: 否
引句:「有故障注入的宣稱，還會確認注入真的發生、而且有斷言。」

查證 file:`tools/verify_claims.py:1115-1141`。injection_problems 的 docstring 寫「只證明有注入、有斷言,不證明注入有意義」;做法是靜態檢查測試或它用的 fixture 有沒有引用宣告的注入手段(`_mentions`),以及測試本體有沒有斷言(`_asserts`)。檔頭 `:7` 也寫「故障注入的證據真的引用了宣告的手段」。

問題:驗證器沒有在執行時確認注入點真的被觸發。「真的發生」會被讀成執行期確認。這句用詞是照 r1 f_2 的建議寫的,屬於前輪建議本身偏強。

建議改法:改成「……還會確認測試真的用了宣告的注入手段、而且有斷言」。

其餘點名的修正句都查過,成立,不報:「程式判不了的就停下交給人」、「花費紀錄不會寫進帳號家目錄的花費帳」、「寫入結果不明與同時處理兩項帶故障注入」、「保留側驗證前 AI 2/9、窮舉 2/10」。
