## Finding 1
severity: minor
blocking: 否
判準:只影響錯誤原因的優先順序,不會產生假值或把不知道變成 0。
- 位置:src/rtb/domain/metrics.py 的 pacing 與 ctr。
- 引句:「problem = _classify(spend, budget, elapsed_fraction)」
- 問題:文件寫「不合理 > 缺漏 > 分母為零」,但跨欄位的不合理檢查(elapsed_fraction > 1、clicks > impressions)只在 `problem is None` 時才做,所以「缺漏」會壓過這兩種不合理。
- 重現:`pacing(None, 100, 2)` 得到 `MetricResult(value=None, reason='missing_data')`,但 elapsed_fraction=2 單獨就已不合理,應為 invalid_data。同理 `pacing(1, None, 1.5)`。
- 佐證:t.py 實跑輸出「pacing(None,100,2) -> MetricResult(value=None, reason='missing_data')」。ctr 因為缺一個欄位就無從比較,不算反例;pacing 的 elapsed_fraction 上限是單欄位檢查,應放進 _classify 之前。

## Finding 2
severity: minor
blocking: 否
判準:輸入是超出 SQLite 範圍的巨大整數,DSP 路徑走不到,只有直接呼叫才會炸。
- 位置:src/rtb/domain/metrics.py 的 _is_valid_amount 與 _ratio。
- 引句:「return _is_number(value) and math.isfinite(value) and value >= 0」
- 問題:math.isfinite 對超過 float 範圍的 int 丟 OverflowError,而不是回 INVALID_DATA;除法同樣可能溢位。函式承諾「不合理就回原因」,卻丟例外。
- 重現:`ctr(2**1024, 1)`、`ctr(10**400, 10**401)` 皆 EXC OverflowError: int too large to convert to float。
- 佐證:t.py 輸出。另外 `roas(1e300, 1e-300)` 與 `roas(5, 1e-320)`(次正規數花費)回 value=inf 且 is_known 為 True,`MetricResult(inf).at_least(10)` 為 True:無限大被當成「有值」通過門檻,應視為 INVALID。

## Finding 3
severity: minor
blocking: 否
判準:是「不支援比較」宣稱與實際行為的落差,以及少數欄位組合語意未定,未造成錯誤結果。
- 位置:src/rtb/domain/metrics.py 的 MetricResult、cvr、pacing。
- 引句:「沒有實作 < > 等比較:誤把空值當數字比大小會直接報 TypeError,而不是默默判成 0。」
- 問題:(a)只擋了排序類比較;`==`、`bool()`、`hash()` 都能用。`bool(MetricResult(None,'no_denominator'))` 為 True,寫成 `if ctr(...):` 會把「不知道」當「有值」;`MetricResult(None,'a') == MetricResult(None,'a')` 為 True。(b)dataclass 可直接建構出 `MetricResult(nan)`、`MetricResult(-1.0)`、`MetricResult(None)`(無 reason),below 與 at_least 對它們照常計算(nan 一律回 False,-1.0 回 False 而不是不知道)。(c)cvr 轉換多於點擊回 5.0,與 ctr 對「點擊多於曝光」判 INVALID 不一致;pacing 在 elapsed=0 且 spend>0 時回 NO_DENOMINATOR(其實是預算尚未開始就已花錢,較像不合理)。
- 佐證:t.py 輸出「bool -> True」「MetricResult(nan) -> False」「cvr(5,1) conv>clicks -> value=5.0」「pacing(5,100,0) -> no_denominator」。建議加 __bool__ 丟錯或至少在文件寫明,並在 __post_init__ 驗「value 與 reason 二擇一」。

## Finding 4
severity: minor
blocking: 否
判準:資料只由測試用的 seed_metrics 寫入,沒有對外寫入面,但讀取面會在髒資料下失真或回 500。
- 位置:src/rtb/dsp/store.py 的 seed_metrics 與 get_metrics,以及 server.py 的 _reply。
- 引句:「values = [fields.get(name) for name in METRIC_FIELDS]  # 沒給的欄位維持 None」
- 問題:seed_metrics 只驗欄位名,不驗型別、範圍、窗口、廣告是否存在。SQLite 型別親和性讓字串與 blob 照存。
- 重現(s.py 與 h.py 實跑):
  - `seed_metrics('c1','1h',impressions='abc')` 之後 get_metrics 回 `impressions='abc'`(字串照樣被當事實回傳)。
  - `spend=float('nan')` 存入後 typeof 為 null:不合理的 NaN 被悄悄變成 None,也就是「INVALID 變成 MISSING」,和領域層的優先順序相反。
  - `spend=float('inf')` 存入後 HTTP 回 `"spend": Infinity`,這不是合法 JSON,嚴格客戶端會解析失敗。
  - `impressions=b'x'` 存入後 GET 回 500 internal_error(json.dumps 對 bytes 丟 TypeError,伺服器端印出堆疊)。
  - `seed_metrics('c1','2h',...)` 與不存在的廣告都被接受,形成永遠讀不到的孤兒列;`impressions=2**63` 丟 OverflowError。
  - 負數(impressions=-5)照存照回,靠領域層擋,這點可接受。
- 佐證:s.py 與 h.py 輸出。另 get_metrics 傳入不可雜湊的 window 會丟 TypeError(`window not in frozenset` 對 list),但 HTTP 路徑只會傳 str 或 None,走不到。
