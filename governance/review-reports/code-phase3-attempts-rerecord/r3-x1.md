### 1. 重複終點列可被其他未結案鍵抵銷，互斥鎖因此失效
severity: major
blocking: 是 會違反 S6，讓同一廣告同時建立多筆未結案嘗試。
引句:「if count < 0:  # 同一把鍵出現第二列終點列,算法的前提不成立:當成毀損,不放行」
file: `docs/rtb-production-agent-demo-knowledge/Projects/RTB_Phase3外部寫入安全_計劃.md:113`

修正只檢查相減後的總數是否為負，沒有檢查「每把鍵最多一列終點」。一筆未結案鍵會把另一把鍵多出的終點列抵銷，使毀損結果剛好為零。

具體重現：

- 輸入：同一廣告已有一把正常未結案鍵；另一把已結案鍵被毀損成兩列終點；再開始第三把鍵。
- 實際：

```text
reported unresolved_count = 0
existing live key = k1-284fa3a15cb51919a1127a448dd43d26d8e4f09bbc863e52f3db68464f320118
third begin created = True state = in_flight
```

- 預期：應回報資料毀損，至少也必須因既有未結案鍵而拒絕；不得寫入第三把鍵。

同一問題也能抵銷全表未結案計數，繞過 S21 的 20 把上限。

### 2. 恢復只接住 ValueError 類毀損，其他讀取錯誤仍會回滾整批
severity: major
blocking: 是 原本要求壞鍵跳過、健康鍵繼續恢復；目前仍可能因單一壞鍵讓整批恢復失敗。
引句:「歷史列讀不回來的鍵跳過並回報:不然一把壞鍵會讓每次重啟都在同一點整批失敗。」
file: `src/rtb/executor/attempt_store.py:169`
file: `docs/rtb-production-agent-demo-knowledge/Projects/RTB_Phase3外部寫入安全_計劃.md:120`

`recover_in_flight()` 雖捕捉 `CorruptedAttemptRow`，但 `_row()` 只把 `ValueError` 轉成該例外。SQLite 表不是 `STRICT`；若 `written_at` 是 BLOB，`written_at.replace("Z", ...)` 會拋 `TypeError`，直接越過跳過邏輯。

具體重現：

- 輸入：兩把 `IN_FLIGHT` 鍵，其中一把的 `written_at` 改成 BLOB `b"bad"`，再執行恢復。
- 實際：

```text
recovery raised = TypeError "a bytes-like object is required, not 'str'"
healthy raw state after rollback = in_flight
```

- 預期：壞鍵出現在 `Recovery.unreadable`；健康鍵提交為 `UNKNOWN`。目前整筆交易回滾，原本問題尚未完全解決。
