## SIDE_BRANCHES 用裸 frozenset 另立一套「無出邊」宣告,跟既有 BACK_TRANSITIONS 的結構化宣告不同套

severity: major
blocking: 是
引句:「SIDE_BRANCHES = frozenset({"a_narrate"})」

對照:`src/rtb/demo/flow.py` 模組層級常數宣告,以及 `tests/demo/test_flow.py` 的
`test_every_node_is_reachable_from_the_start_and_every_end_is_a_dead_end`。

專案裡「這個節點不准有出去的邊」這個結構性不變量,原本只有兩套宣告方式共同撐住:
`NodeKind.TERMINAL`(節點本身的 kind)和 `BACK_TRANSITIONS`(`flow.py` 第 112 行起的
`BackTransition` dataclass,欄位有 `node`/`what`/`lane`/`returns_to`/`transition`/
`lifecycle`,`_graph()` 還會用它產生對應節點,自帶「為什麼沒有出邊、回到哪裡」的說明)。
`test_every_node_is_reachable_from_the_start_and_every_end_is_a_dead_end` 原本就是靠
`kind is NodeKind.TERMINAL or graph_node.id in loop_nodes`(`loop_nodes` 從
`BACK_TRANSITIONS` 算出來)兩條件判斷「這節點合法沒有出邊」。

這次新增的 `SIDE_BRANCHES` 是第三種宣告:既不是 `NodeKind` 的成員(`a_narrate` 在
`_NODES` 裡仍是 `S`,沒有像結束點一樣標成 `T`),也不像 `BACK_TRANSITIONS` 那樣用結構化
dataclass 記下「回到哪裡、對應哪個狀態轉換」,而是照抄 `AI_NODES`(`frozenset({"a_narrate"})`,
本來是用來標「這個節點歸屬是 AI」的分類標記,跟「這節點有沒有出邊」這個結構性質完全無關)的裸
frozenset 寫法,只放節點 id 字串,靠旁邊一段註解交代理由。測試也因此被迫從兩路判斷改成三路
判斷(`kind is TERMINAL or id in loop_nodes or id in SIDE_BRANCHES`),把同一個不變量拆成
三套彼此獨立、互不相干的宣告位置。

建議改法:既然 `a_narrate` 這類「送出後才做、沒有出邊」的節點,語意上跟 `BACK_TRANSITIONS`
處理的「沒有出邊、但有明確理由」是同一種結構性質,應該沿用 `BACK_TRANSITIONS` 那套結構化宣告
(或至少讓 `NodeKind` 多一個像 `TERMINAL`一樣參與圖形驗證的成員),而不是新開一個只給字串 id、
只在測試裡另外判斷的 frozenset。若要保留輕量寫法,至少不要沿用 `AI_NODES` 這個語意完全不同
(節點歸屬,不是拓樸結構)的既有常數當範本,以免之後有人以為「旁支」判斷跟「AI 節點」判斷是同一
族的東西。
