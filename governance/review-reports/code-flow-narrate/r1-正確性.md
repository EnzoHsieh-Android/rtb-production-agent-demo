## F1 旁支的邊從「送出」出發,但說明只替收件收下的建議寫;圖跟自己的標籤互相矛盾

severity: minor
blocking: 否
引句:「("a_submit", "a_narrate", "收件收下之後另外寫說明(只給人看,執行時不讀、不等它)"),」

**查證**
- analyzer/narrate.py 的 `narrate_pending` 只讀 `TaskStore.handed_off_rows`,也就是 state = HANDED_OFF 的列。
- analyzer/flow.py 的 `_from_proposed` 裡,只有收件口回 `Accepted` 時才轉成 HANDED_OFF。`SubmitStale` 會轉回 COLLECTING_EVIDENCE,對到 `a_restale`;`SubmitRejectedPermanently` 會轉成 FAILED,對到 `a_failed`。
- demo/flow.py 自己的 `_PLACES[TaskState]["HANDED_OFF"]` 也把 HANDED_OFF 放在 `_on("i_check", "x_pending", "執行端已收下")`。

所以程式的事實是:說明在「收件檢查 → 收下」之後才寫,被拒收或送到時已過時的建議不會有說明。新邊卻從 `a_submit` 岔出,位置在 `i_check` 這個判斷點之前。圖讀起來是每份送出的建議都會寫說明,跟邊自己的標籤「收件收下之後」矛盾。

README 動圖也有同樣的問題:
- make_agent_flow_gif.py 的 `EDGES` 從 `submit` 拉虛線到 `narrate`,註記寫「送出後另寫」。
- 同一格的 `CAPTIONS["narrate"]` 卻寫「提案送進收件口後」。
- 在第 8 格(送出提案高亮)裡,主線 送出→收件 已經變暗,旁支卻仍然是亮的。看起來說明跟送出同時發生、比收件檢查還早。

**重現**
1. 讀 narrate.py 的 `narrate_pending` 與 task_store.py 的 `handed_off_rows`。
2. 對照 demo/flow.py 的 `_PLACES` 裡 `TaskState` 那一段,以及 `_EDGES` 裡 `i_check` 的五條出邊。
3. 抽 agent-flow.gif 第 8 格目視。

**建議修法**(二擇一)
1. 保留從 `a_submit` 出發的畫法,但節點、邊標籤與 GIF 註記要寫明條件。例如邊標籤寫「收件收下的才另外寫說明(被拒收或過時的不寫;只給人看,執行時不讀、不等)」,GIF 註記寫「收件收下後另寫,只給人看,執行端不讀」。
2. 讓旁支真的從收下之後出發,例如 `x_pending → a_narrate`。GIF 則從收件檢查或待處理佇列拉虛線。這種做法要讓 `render_untaken_branches` 跳過目標在 `SIDE_BRANCHES` 的邊,不然每個情境都會把它列成沒走的分支;測試也要跟著改成斷言進邊來自收下之後的節點。

## F2 核可表單寫的「沒附說明」理由不符事實

severity: minor
blocking: 否
引句:「這張表單沒有附 AI 說明：說明在建議送出之後才另外寫、只給人看，」

**查證**
- demo/present.py 的 `build_demo_state` 組 `ApprovalForm` 時寫死 `narrative=None`。
- driver.py 的 `DemoRunner.run_one` 在 `_attempt` 整段結束之後才呼叫 `run_model_entries`,人工確認就在 `_attempt` 裡面。
- 表單出現時(F7 停在 `x_wait_approval`),建議早就送出並被收件收下了。

所以「說明在建議送出之後才寫」解釋不了表單為什麼沒有說明:表單出現的那一刻,已經是送出之後。真正的原因有兩個:
- 一鍵展示要等情境整段跑完才產說明。
- 表單組裝時本來就不讀說明。

正式或即時路徑也一樣。說明命令列是獨立跑的,核可時說明可能已經寫好,表單照樣不會帶(因為寫死 None)。現在這段文字會讓人以為「等一下、或者送出之後就會有」。

**重現**
1. 讀 present.py 的 `build_demo_state` 中 `approval = ... ApprovalForm(... narrative=None ...)` 那一段。
2. 對照 driver.py 的 `DemoRunner.run_one` 的呼叫順序。
3. 測試 `test_the_approval_form_does_not_promise_an_ai_narrative_it_never_gets` 只檢查字串有沒有出現,不檢查理由對不對。

**建議修法**:改成照實寫,例如「這張表單不帶 AI 說明:核可只看程式算出的數字;展示在情境跑完後才產說明,執行時也不讀、不等它」。page.py 的 `_model_text` 註解同步改。
