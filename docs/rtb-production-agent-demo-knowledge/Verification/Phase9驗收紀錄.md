## 偏離與缺口

- 增量 1 還沒收尾,上面凡標「待補」的都還沒驗;CI 結果與推送提交編號沒有。
- 服務水準的數值全是示範值,沒有正式環境基準;示範的縮短倍數下,真實時間的突波會被放大成告警,不適合直接接正式通知。
- 事件表只增不改、不清除,會一直長。
REVISIT:2027-03-31 若事件表超過 100 萬列或資料庫檔明顯變大,加維運用的封存指令(搬到歸檔檔,不是刪除)。
- 指標每次即時算一個窗、不留時間序列;延遲分位數把窗內樣本整批讀進記憶體排序;結果不明現況的成本隨嘗試歷史長。
REVISIT:2027-03-31 若要長期看趨勢或接外部監控,改成定時把窗結果寫進只增不改的指標快照表。
REVISIT:2027-03-31 若嘗試紀錄超過 100 萬列,或告警要每分鐘查一次以上,改成維護一份未結案小表。
- 燒損評估器不存告警狀態,接通知時要另外處理去重與抖動;增量 3 之前的舊寫入沒有核對材料,判成無法核對、另報份數。
- DSP 呼叫紀錄在「DSP 回應之後、寫紀錄之前」當機時會少一筆;追蹤檢視的三個來源不是同一個快照,一直忙時照實標可能不一致。
- 稽核守衛是掃原始碼的結構檢查,防忘記不防刻意繞過。
- 實演不帶分析行程、DSP 提交時間不接虛擬時鐘;回頭條件:分析端補上時鐘注入點時(事件入口:[[Systems/分析行程流程與檢查點]] 的改動),把分析行程接回實演。
- DSP 時鐘倒退時提交時間墊高到上一筆,重查已過窗可能多出後來的寫入;照規格 [S667] 駁回,留使用者覆核。
