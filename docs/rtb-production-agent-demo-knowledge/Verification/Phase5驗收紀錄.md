## 偏離與缺口

- 重新規劃只在呼叫端給推進函式操作查詢時發生;分析行程還沒有啟動程式,目前沒有任何正式呼叫端會給。F4 合約原文照實寫明這個前提(使用者裁定)。
- 收件表清掉(保留期 2 小時)之後 DSP 查不到寫入時,一律重新規劃,分不出當初是版本已變、死信還是權限類擋下;代價是清掉之後死信也會重做,受代數上限約束(使用者裁定的範圍擴大)。
- 收件口回給分析行程的擋下原因,權限類合併成「不允許」,分析行程看不到細分原因(使用者裁定,防止試出預算上限與租戶歸屬);細分代碼只在執行端紀錄。
- 兩條重跑檢查路徑確認成版本已變,但嘗試結果代碼記「沒發生」;同一決策重送新修訂時會拿到「同一操作先前已失敗」。分析行程永遠只送修訂 1,目前碰不到。
- 舊任務(Phase 5 之前交給執行的)沒有存冪等鍵,只能從提案重算;冪等鍵前綴由測試釘住,改算法前要先回填。
- 分析側代碼審第 3 輪折入的補欄位競態修正,改到正式程式但已到輪數上限,沒有再經全新席覆核;證據是先紅後綠測試與變異檢查。
- F4 端到端那支用 light 分級審,處置帳沒有輪次、判定沒有凍結(工具限制,見另一個工作區的回報)。
- 指標只是唯讀查詢,沒有告警與時間序列(Phase 9);執行前檢查擋下的版本已變只記在收件表,會被清,長期計數要等 Phase 9。
