# 現行規則只看有沒有投放就提案


## 發生什麼事
- 2026-09-26 模擬面試官試讀 repo,看到評估表「現行規則 12/36、暫停格 0/4」卻說正式決策用規則,追問才查出規則本身太粗。
- 暫停的廣告靠執行端「不在投放」擋下,不會寫;啟用中、有點擊沒轉換的廣告會被提案並寫入(只受單筆與 24 小時累計上限約束)。

## 要做的(當時紀錄,2026-09-26 已修,現況見〈結案〉)
- 另開計劃把九條判斷搬進正式規則,規則模式也要查四種追加資料;既有測試與合約跟著改。

## 結案(2026-09-27 補標;實際在 2026-09-26 Phase 14 增量 2b 修好)
- 修法:正式決策改用九條判斷(順序是新鮮度、可信現況、第 1/2 條只用基本資料、配速、其餘七條要四種追加資料),四種追加資料由分析端規則輪分三步讀;舊的「曝光點擊正數就值得加」判法整段撤掉。出處 [[Projects/RTB_Phase14正式規則照九條判斷_計劃]]〈實作解讀〉增量 2b;現行規則以程式碼為準:`rg -n "def code_rule|def decide" src/rtb/analyzer/policy.py src/rtb/analyzer/rule_round.py`。
- 防回歸:[test:test_paused_and_anomalous_campaigns_finish_from_base_evidence](暫停與資料異常只用基本資料結案、不提案)、[test:test_the_frozen_old_rule_stays_as_history_and_nine_rule_differences_are_listed](舊判法凍結當歷史,列出九條跟它的差異);2026-09-27 本機重跑兩支都過。Phase 13 名稱正常 36 筆的程式規則列見 [[Systems/評估與Jev決策點]]〈報告三列分列〉。
- 為什麼拖到現在才結案:Phase 14 修完沒人回頭改這篇的狀態;它的 about_code 掛在決策規則那支檔,改那支檔時會被推到眼前、講的卻是已經不存在的問題。這次在 [[Issues/Phase14後筆記漂移清理]] 一起處理。
