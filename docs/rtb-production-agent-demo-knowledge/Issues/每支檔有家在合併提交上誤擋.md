# 每支檔有家在合併提交上誤擋

## 發生什麼事

- 2026-09-24 Phase 9 推送:三個合併提交(540ef0a、6742fb9、96415b1)把另一邊帶來的筆記改動(共用行程基礎、稽核表只增不改守衛、調查實演)跟不是那幾篇家的程式檔算在同一個提交,擋了 3 條。協調者把這道檢查暫設成只警告也照樣擋(之後已還原,設定沒動)。見 [[Verification/Phase9驗收紀錄]]。
- 2026-09-24 Phase 10 推送:合併提交 65150b1 把決策規則的改動與評估家筆記放在同一個合併提交,又被擋。見 [[Verification/Phase10驗收紀錄]]。

## 原因

逐提交判定「這次寫了說明的筆記是不是這次改動檔的家」時,合併提交的改動是兩邊合起來算的:另一邊早已各自配好家的筆記改動,在合併提交裡跟這邊的程式檔湊在一起,就被當成「寫了說明卻不是改動檔的家」。本機提交時這道檢查對合併提交是跳過的(提交時印「合併提交跳過,推送前會把合併的結果整段查一次」),推送前的整段檢查才擋。

## 這邊的處置

兩次都由協調者先手動跑其他檢查(規格閘、代碼審檢查、受波及合約測試)全過,再用 --no-verify 推送;本機沒有留痕,只記在當次的驗收紀錄。

## 要做的

- 回報 lumos 工具鏈:合併提交的逐提交家判定要把兩邊各自的改動分開算,或對合併提交只看它相對第一個父提交新帶進來的配對。不在本專案修。
- 在工具修好之前,推送含合併提交的分支時,先試著把本機還沒推過的提交整理成線性(rebase),避免合併提交;已經合進 main 的提交不改寫。

REVISIT:2026-12-31 下次推送含合併提交時先試 rebase 成線性提交再推;若到這天工具鏈已修好,確認一次後把這篇結案。
