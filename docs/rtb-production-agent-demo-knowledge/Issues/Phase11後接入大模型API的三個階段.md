# Phase11後接入大模型API的三個階段

## 使用者要的(2026-09-24,使用者本人)

- 在必要階段串接大模型 API,時機:Phase 11 之後、Phase 12 之前,另開一個階段,讓 Phase 12 的 HTML 能展示模型那一步怎麼被關卡管住。
- 三個接入點:
  1. 異常原因假說與調查建議:指標異常時讀追蹤與指標,提出原因假說與下一步;只給建議、不下決定。Phase 0 路由表原本就把這類「多證據模糊推理」劃給模型。
  2. 分析端提案的風險說明:模型依證據寫提案的風險說明文字;決策照舊由程式規則下,文字當不可信輸入(沿用 Phase 7 信任邊界)。
  3. 「值不值得加」的候選:接進 Phase 10 評估機制,實測品質、成本、延遲;預期結論仍是不採用(評分表可由程式精確算出),但比較表會有實測數字。

## 開工時必須處理的邊界(Phase 0 架構筆記已預告)

- 對外連線:第一次連外部服務;只在明確開啟時才連,預設不連。
- 金鑰:只從環境變數讀、不進程式庫;CI 沒有金鑰,測試用錄好的回應或假的模型用戶端,真實呼叫只在本機展示時跑。
- 信任邊界:模型輸出一律當不可信輸入,不能直接下決定、不能繞過執行端任何關卡;接入點 3 走 Phase 10 的候選協定(經共用 HTTP 用戶端、帶截止時間、失敗退回現行規則)。
- 成本與延遲:每次呼叫記花費、延遲、失敗率;接入點 3 的成本延遲門檻照 Phase 10 規定由使用者在接上第一個候選時裁定。
- 要問使用者:用哪一家、哪個模型;每次展示的花費上限。(已問,見下節)

## 使用者裁定(2026-09-24,使用者本人)

- 供應商:Anthropic Claude。
- 預設模型:Sonnet 5(模型代號 claude-sonnet-5)。
- 花費上限:每次展示 1 美元、每月 20 美元;到上限就停止呼叫模型,改顯示「已達上限」,不默默繼續花。
- 沒設金鑰時:一鍵展示碰到模型階段改用錄好的回應,頁面清楚標示「這段是錄製回應,不是即時呼叫」;CI 同樣走錄好的回應。
