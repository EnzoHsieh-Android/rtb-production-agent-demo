# 服務水準與燒損告警

本篇管三支檔:`src/rtb/ops/slo.py`(設定表、週期統計、錯誤預算、燒損評估器、命令列 `python -m rtb.ops.slo --executor-db … --analyzer-db … --dsp-url … --now …`)、`src/rtb/ops/sli.py`(六條服務水準指標在一個窗裡的計數)、`src/rtb/ops/side_effects.py`(副作用核對與讀 DSP 的窗)。設計與合約 [S650]–[S667] 見 [[Projects/RTB_Phase9可觀測與SLO_計劃]] 增量 3。

- 資料來源:[[Systems/提案收件口]] 的窗內事件、各任務事件與核可使用紀錄(批量);[[Systems/外部寫入嘗試紀錄]] 的結果不明窗口讀取、一批鍵的第一列、同一份提案的第一列;[[Systems/分析行程流程與檢查點]] 的接續關係與根任務;[[Systems/Mock-DSP]] 的兩支列操作唯讀端點與依冪等鍵讀操作。跟 [[Systems/有界標籤的指標]] 共用維運套件的讀取白名單與唯讀開法。
- 評估器不自己讀時鐘,每個窗從傳入的「現在」與設定表算出,交給計數函式;查詢次數固定(有目標的四條各 4 個窗加週期統計,目標為零的兩條各週期統計)。防回歸:[test:test_the_burn_evaluator_reads_only]。
- 週期統計把週期切成每段不超過 24 小時、首尾相接的子窗逐段相加;縮短倍數是 1 時一條指標要查 30 段。防回歸:[test:test_the_period_is_summed_from_day_sized_windows]。
- DSP 讀不到時,兩條目標為零的指標回「資料來源缺」,不當成 0 個事件;其餘四條照常。違規欄:週期內已看到壞事件就是違規,沒看到壞事件又有子窗缺資料才為空(代碼審第 1 輪)。「讀不到」包含:連不上、狀態碼不對、欄位或提交時間讀不懂(沒帶時區也算)、重複核對第二段逐鍵查失敗。防回歸:[test:test_the_dsp_being_unreachable_is_missing_not_zero]、[test:test_a_malformed_commit_time_from_the_dsp_is_unreadable_not_a_crash]、[test:test_a_failed_lookup_of_a_sibling_key_makes_duplicates_missing]、[test:test_a_single_zero_target_violation_fires_for_the_whole_period]。
- 評估器只隔離資料來源讀不到:一條讀不到只把那一條標資料來源缺並把原因記在 error 欄,另外五條照算;程式錯誤、資料庫毀損、找不到資料庫檔、資料庫還沒升級一律往外丟(代碼審第 2 輪:第 1 輪連程式錯誤都吞,命令列還回 0)。防回歸:[test:test_one_unreadable_slo_does_not_hide_the_others]、[test:test_a_programming_error_or_a_broken_database_is_not_swallowed]。
- 穩定欄:端到端交給執行三輪都讀到不同時回最後一輪並標不穩定,每條狀態都帶這一欄;副作用核對兩條依因果順序恆為穩定(理由寫在副作用核對模組說明)。防回歸:[test:test_an_unstable_cross_database_read_is_reported]。
- DSP 的列操作兩支端點要帶唯讀稽核金鑰(環境變數名稱與標頭寫法見 [[Systems/寫入能力憑證]] 的共用格式模組;專用標頭,放金鑰位元組的 base64url,非 Latin-1 金鑰也送得出)。命令列入口從環境讀,沒設就讀不到 DSP 的窗,照實標資料來源缺、回結束代碼 8。防回歸:[test:test_a_non_latin1_audit_key_goes_through]。
- 批量讀的第一列帶「快照對得上鍵」旗標(見 [[Systems/外部寫入嘗試紀錄]]):重複核對遇到快照讀不回來算無法核對,讀得回來卻對不上鍵時證實有更早的同內容提交才判壞、否則無法核對,絕不算好;未授權核對不拿這種快照核授權範圍。DSP 舊操作沒記預期版本比照政策版本判無法核對。防回歸:[test:test_a_first_row_whose_snapshot_does_not_match_its_key_is_never_good]、[test:test_unverifiable_writes_are_reported_apart_from_the_denominator]。
- 缺資料的原因(DSP 讀不到的分類、狀態碼與 DSP 回的錯誤代碼,不含金鑰與標頭值)帶在計數上,週期取第一個,放進狀態的 error 欄並印在標準錯誤(代碼審第 3 輪)。防回歸:[test:test_the_command_line_says_why_a_source_was_missing]。
- 結束代碼:0 成功;2 資料庫檔不存在;3 資料庫還沒升級;6 稽核金鑰超過長度上限(設定錯誤,沿用指標的代碼);5 有指標跨資料庫讀了三輪都不同(照樣印出最後一輪,沿用指標的代碼);8 有指標缺資料或出錯(照樣印出每一條,哪幾條、為什麼印在標準錯誤;跟 5 同時成立時回 8;代使用者裁定)。防回歸:[test:test_the_command_line_reports_fixed_exit_codes]。
- 整合增量 2 修正後(2026-09-24):命令列改用維運套件共用的參數解析([[Systems/追蹤檢視]] 管的那支),參數錯或 --now 沒帶時區回 7,不再用 argparse 預設的 2 跟「資料庫檔不存在」撞號。防回歸:[test:test_the_slo_command_line_reports_bad_arguments_apart_from_a_missing_database]。
