- `src/rtb/demo/launcher/child.py`:子行程裡的故障啟動器,核對交付之後帶著故障跑正式入口。
- `src/rtb/demo/faults/__init__.py` 只是套件宣告;`src/rtb/demo/faults/delivery.py` 寫與核對故障設定檔;`src/rtb/demo/faults/dsp.py` 是帶故障排程的模擬 DSP(照 F1 端到端測試的組法:每個會改狀態的請求依序取一個故障與時鐘偏移);`src/rtb/demo/faults/executor.py` 是執行迴圈的猝死點與時鐘偏移(照 F2、F3 端到端測試的組法)。

## 驅動程式與展示狀態

- `src/rtb/demo/state_store.py`:展示狀態暫存資料庫。驅動程式寫(每次寫入一條短連線),伺服器用唯讀開法讀;記情境起訖與結果、每筆判斷(帶來源)、目前節點、F7 的各節點筆數。
- `src/rtb/demo/observe.py`:把系統紀錄觀察成判斷紀錄,與交叉核對的必經節點比對。
- `src/rtb/demo/driver.py`:驅動程式與情境。每個情境在展示根目錄下自己的子目錄起一組真的行程(模擬 DSP、收件口、執行迴圈、分析端驅動),輪詢觀察、寫進展示狀態,最後斷言必經路徑與平台真實狀態;斷言沒過、行程起不來、超過時限都標「沒跑完」並寫原因。F1 用 DSP 故障排程(提交前逾時),F2、F3 用執行迴圈猝死點,重啟時執行迴圈與平台一起帶 5 分鐘時鐘偏移;F3 另用兩條執行緒搶同一件工作,驗只有一方付費。F4 由驅動程式扮另一個寫入者搶先改廣告;F5 用對抗樣本裡的情境題原文當廣告名稱;F6 讓執行迴圈連不到平台、停下等人處理後改廣告再重新送入;F7 是 300 個廣告、門檻 1234、8 個工作者打真的模擬 DSP(本機一次約 9 秒)。
