# 一鍵展示

Phase 12 的展示套件。計劃:[[Projects/RTB_Phase12一鍵展示與HTML報告_計劃]]。

## 啟動與故障交付

- `src/rtb/demo/keys.py`:每次展示的三把金鑰(能力、稽核、核可),文字形式;`repr` 不印金鑰。
- `src/rtb/demo/launcher/__init__.py`:子行程啟動(`start`,獨立行程群組,`stop` 連孫行程一起結束)、環境白名單(`child_env`)、展示根目錄(`prepare_root`,寫標記檔)、把故障請求交給故障套件寫成設定檔(`write_fault_plan`)。沒排故障的子行程直接跑正式入口(`python -m` 正式模組)。
- `src/rtb/demo/launcher/child.py`:子行程裡的故障啟動器,核對交付之後帶著故障跑正式入口。
- `src/rtb/demo/faults/__init__.py` 只是套件宣告;`src/rtb/demo/faults/delivery.py` 寫與核對故障設定檔;`src/rtb/demo/faults/dsp.py` 是帶故障排程的模擬 DSP(照 F1 端到端測試的組法:每個會改狀態的請求依序取一個故障與時鐘偏移);`src/rtb/demo/faults/executor.py` 是執行迴圈的猝死點與時鐘偏移(照 F2、F3 端到端測試的組法)。

## 驅動程式與展示狀態

- `src/rtb/demo/state_store.py`:展示狀態暫存資料庫。驅動程式寫(每次寫入一條短連線),伺服器用唯讀開法讀;記情境起訖與結果、每筆判斷(帶來源)、目前節點、F7 的各節點筆數。
- `src/rtb/demo/observe.py`:把系統紀錄觀察成判斷紀錄,與交叉核對的必經節點比對。
- `src/rtb/demo/driver.py`:驅動程式與情境。每個情境在展示根目錄下自己的子目錄起一組真的行程(模擬 DSP、收件口、執行迴圈、分析端驅動),輪詢觀察、寫進展示狀態,最後斷言必經路徑與平台真實狀態;斷言沒過、行程起不來、超過時限都標「沒跑完」並寫原因。F1 用 DSP 故障排程(提交前逾時),F2、F3 用執行迴圈猝死點,重啟時執行迴圈與平台一起帶 5 分鐘時鐘偏移;F3 另用兩條執行緒搶同一件工作,驗只有一方付費。F4 由驅動程式扮另一個寫入者搶先改廣告;F5 用對抗樣本裡的情境題原文當廣告名稱;F6 讓執行迴圈連不到平台、停下等人處理後改廣告再重新送入;F7 是 300 個廣告、門檻 1234、8 個工作者打真的模擬 DSP(本機一次約 9 秒)。

## 流程圖怎麼對到系統

- `src/rtb/demo/flow.py` 是流程圖本身:48 個節點(24 個一般步驟、17 個判斷點、7 個結束點,其中 10 個是回頭節點)、68 條分支,五條泳道;另外放系統結果對應表、判斷點綁定表、回頭轉換清單與禁用術語掃描。`src/rtb/demo/state.py` 是頁面與伺服器共用的資料結構(Codex 那份的原樣複本);`src/rtb/demo/__init__.py` 只是套件宣告。

- 節點的內部編號用 a_(分析)、i_(收件)、x_(執行)、p_(廣告平台)、h_(人工)開頭;顯示給人看的是標籤。
- 對到的列舉來自這幾處的家:[[Systems/提案收件口]](處置、擋下原因、死信原因、停下種類、生命週期事件、重放結果)、[[Systems/執行迴圈]](作廢結果、執行迴圈結果)、[[Systems/任務流程領域模型]](任務狀態、嘗試狀態、結果代碼)、[[Systems/分析行程流程與檢查點]](重新規劃原因、分析端路由、不提案原因)。
- 一個成員可以對到節點或邊,好幾個成員可以對到同一條邊(例如六種執行前檢查沒過都在「寫入前再確認 → 擋下」這條邊上),白話說明各自不同;判斷紀錄表顯示的是成員自己的白話,圖上顯示的是邊的標籤。
- 驅動程式(增量 1 之後的部分)記判斷時,用這份對應表把系統實際的結果換成圖上的邊與白話原因。
