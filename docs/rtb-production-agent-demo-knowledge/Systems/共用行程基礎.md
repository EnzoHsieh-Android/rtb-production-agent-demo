# 共用行程基礎

`src/rtb/httpkit.py`(httpkit)提供伺服器與處理程式基底(含故障注入標頭的開關 `read_fault`:啟動時沒開旗標就一律拒絕 X-Fault):子類別實作 handle_request,需要時覆寫 map_exception 把自己的例外對應成錯誤回應。`src/rtb/sqlitekit.py`(sqlitekit)提供連線與寫入交易。使用者見 [[Systems/Mock-DSP]] 與 [[Systems/提案收件口]]。`sqlitekit` 另提供 `is_integer_overflow`(F7 效能計劃:資料庫整數加總溢位只回一般錯誤碼、跟查詢寫錯同一個碼,只能再看訊息文字「integer overflow」;這是專案唯一要看訊息的判斷,集中在這裡跟「是不是鎖競爭」並排,SQLite 改了措辭只改一處;防回歸 [test:test_only_the_integer_overflow_error_counts_as_overflow])、`immediate_transaction`(進入時 BEGIN IMMEDIATE、正常結束提交、任何例外回滾),收件表用它,避免各處重寫 COMMIT/ROLLBACK 樣板。

已知缺口(如實標明):
- 整個請求的總期限(預設 30 秒)會切斷「處理中」的回應:DSP 故障注入的 hang_seconds 必須小於它,否則模擬的「提交後才回應」會被期限先切斷,行為不同。目前預設 2 秒遠小於 30。
- 每個接受的連線多一條計時器執行緒,結束時取消並很快退出(有測試確認不留下);連線上限只界定同時處理中的連線,不界定計時器執行緒的建立速率。
- 連線上限是全域的:本機一個慢速用戶端佔滿名額,就會擋住合法呼叫者。目前這個服務只給本機的單一呼叫者用,所以接受這個風險。
REVISIT:2026-10-20 見上面每來源連線配額的評估,一起決定。
- 整個請求的期限用計時器切斷連線,不是精確的逐位元組限速;期限內仍可佔住一條執行緒,連線上限也是全域的、不分來源。

## 唯讀連線與程式版本(Phase 9 增量 1,2026-09-24)

- 唯讀連線以 SQLite 官方 URI 的 mode=ro 開,並明講這是 URI;檔案不存在丟「找不到檔案」,不建新檔。PITFALL: 把「mode=ro」字串丟給一般的連線函式不會報錯,而是在磁碟上悄悄新建一個以那串文字為檔名的空資料庫(計劃前掃實測)。檔名轉 URI 用路徑的標準轉法,檔名帶井號、問號、空白也開到同一個檔。防回歸:[test:test_the_read_only_connection_really_is_read_only]。
