# 任務流程領域模型

第五支 `src/rtb/domain/attempt.py` 是執行行程這一側的外部寫入嘗試:不合法轉換的例外(比照任務狀態機,定義在領域層)、冪等鍵函式、嘗試狀態機(唯讀轉換表,轉人工與自轉換不在一般轉換裡)、結果代碼與細節文字檢查,儲存在 [[Systems/外部寫入嘗試紀錄]]。

四支檔案:`src/rtb/domain/_checks.py` 放領域層共用的小檢查(識別碼格式、整數不含布林、數字不含布林、時間帶時區;證據、提案與 [[Systems/外部寫入嘗試紀錄]] 共用這一份時區判斷,各模組不再自己寫,有測試擋;另有一支「每一個都要帶時區,否則丟固定訊息的 ValueError」的檢查,嘗試紀錄、[[Systems/分析行程流程與檢查點]] 的任務歷史與 [[Systems/有界標籤的指標]] 都呼叫它,原始碼掃描擋住三處再自己寫判斷式(Phase 9 增量 2 代碼審第 2 輪),防回歸 [test:test_time_zone_checks_are_not_written_again_elsewhere]),讓同一個規則只有一份定義;指標計算([[Systems/確定性指標計算]])也用其中的「數字不含布林」。其餘三支模組:`src/rtb/domain/task_state.py` 是狀態機,合法轉換是一張表,終點狀態沒有出路,非終點都可以轉失敗,分析或已提案階段可以因證據或提案過期回到蒐集證據,交接之後不行;`src/rtb/domain/evidence.py` 是證據型別與 `check_freshness`,先判年齡再判版本,結果分新鮮、過期、版本已變、未驗證四種,只有新鮮可用;`src/rtb/domain/proposal.py` 是提案型別與 `parse_proposal`,把不可信的原始資料解析成提案或一份完整的錯誤清單,時間欄位限定在 2000 到 2100 年(換成 UTC 不會溢位)、決策從建立到到期最多 1 小時(否則一份提案能無限期佔住收件名額,見 [[Systems/提案收件口]]);另有 `content_hash`(提案內容的 SHA-256:時間換成 UTC、鍵排序、串列順序有意義;序列化格式有測試釘住,因為雜湊會存進收件表,改格式會讓升級後的重送被誤判成衝突)。三者都在領域層,由該目錄的 ruff 設定禁止匯入資料庫、網路與模型。

## 已知缺口(如實標明)

- 只有分析行程這一側的狀態機;執行行程那一側的操作狀態、事件與 trace 尚未定義,屬後續增量。
- `parse_proposal` 最外層有一道保底:萬一有東西讓解析丟例外(例如刻意會丟例外的自訂物件,真實 JSON 輸入走不到),只回一個 `unexpected_failure:<例外型別>` 錯誤,不讓例外逃出去。這是安全邊界的最後一道防線,由 [test:test_even_hostile_python_objects_that_raise_are_turned_into_an_error_result] 守著。
- `task_state.py` 匯入時會檢查轉換表涵蓋所有狀態(漏了就匯入失敗),測試裡也有同一條斷言;兩處都守是有意的:測試只在開發時跑,而匯入時檢查讓漏表的程式根本起不來,不會拖到執行時才 KeyError。
- 提案解析只檢查格式,不做政策或授權檢查;大小是粗估的位元組數(字串用 UTF-8 位元組、整數用位數估算、每個容器有固定開銷),不是精確的 JSON 長度,目的是擋超大與過深,不是量準;新鮮度的年齡上限由呼叫端傳入,還沒有集中的政策。
- 風險摘要目前只是不超過 500 字的字串,沒有結構。
- 這個增量沒有經過設計審;狀態機與證據格式在增量 2 設計審前先定型,審查員可能要求修改。

型別檢查:2026-09-22 起這一層通過 mypy 嚴格模式。判斷函式(`is_plain_int`、`is_id` 等)用 `TypeGuard` 標明通過後的型別,讓型別檢查能驗證邊界判斷;行為沒有改變,既有測試全部通過。由 [[Systems/靜態檢查閘]] 的三層守衛持續檢查。
