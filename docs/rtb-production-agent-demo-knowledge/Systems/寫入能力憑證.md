# 寫入能力憑證

REVISIT:2027-01-31 Phase 6 做租戶隔離與權限時,決定作廢要不要改成按租戶隔離的命名空間。

兩支檔:共用的 `src/rtb/capabilitykit.py`(格式機制與讀金鑰),執行行程的 `src/rtb/executor/capability_signer.py`(簽發器、安全讀租戶設定)。DSP 端的驗證在 [[Systems/Mock-DSP]]。

## 簽作廢(Phase 3 增量 4)

- 簽發器新增「簽作廢」:聲明的動作是 void_operation、新預算為空值、預期版本取快照觀察到的版本;只檢查廣告屬於允許的租戶,不檢查預算上限——作廢是撤掉一個寫入,不是在寫。設定檔壞掉或不安全照舊丟拒簽例外,由執行迴圈當系統故障停機。DSP 端的聲明動作清單與本文白名單多同名成員,驗證順序不變(見 [[Systems/Mock-DSP]])。防回歸:[test:test_voiding_needs_a_void_capability_scoped_to_the_key]

## 總曝險門檻(Phase 6 增量 1,2026-09-23)

- 租戶設定檔每個租戶多一欄「24 小時內加預算總額上限」。缺這欄當 0(這個租戶不准加預算,擋下並留紀錄,其他租戶照常),不讓一個租戶漏填就讓整份設定檔停機;有寫但值不合法(負數、不是整數、超過整數上限)仍照既有規則整份不合法、停機——打錯字跟沒設不一樣。
- 簽發器多一個方法,在同一次讀設定檔時把租戶與門檻跟憑證一起帶回,給開始一筆比對額度用。
