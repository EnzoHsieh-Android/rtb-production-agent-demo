# 正式九條判斷領域規則

`src/rtb/domain/nine_rules.py` 收四查詢不可變型別與封閉判定原因,由同一決策時鐘判斷最近三天。第 1、2 條可只靠基本輸入定案;其餘條件要求四查詢都有結果。第 4、5 條僅資料齊全且分母零時略過;必要列內缺值、七日任一天 no_data、查詢沒有結果與輸入建不成均回九格之外的證據不足。

2026-09-26 代碼審折入:歷史預算調整先掃完全部列,任一列缺時間(含沒時區)就保守回無格證據不足,否則任一近期列才命中第 3 條,與列序無關;逐日及過去調整任一列負數或欄位不自洽亦回無格的 `invalid_row_value`。資料類別建構時驗結構與數值型別,保留缺值及負數給判定函式診斷;決策時鐘沒時區直接丟 `ValueError`(同 [[Systems/任務流程領域模型]] 的 `WorthInputInvalid` 例外家族,這是呼叫端違約而非查詢證據不足)。區段轉換率只由領域公開函式計算,評估邊界亦呼叫它。[test:test_history_missing_time_is_insufficient_in_either_row_order] [test:test_invalid_daily_row_is_insufficient_before_segment_aggregation] [test:test_eval_uses_the_domain_segment_rate]

WHY: 2026-09-26 增量 1 先搬領域與評估標準答案,保留正式送件流程原行為,讓後續增量能在同一組可逐筆回歸的資料上接線。出處:[[Projects/RTB_Phase14正式規則照九條判斷_計劃]]〈拆增量〉1。

`tests/domain/test_nine_rules.py` 守這支模組的邊界:列內缺值、單日 no_data、分母零略過與精確門檻,以及領域層只匯入白名單標準函式庫。

2026-09-26 增量 2 的一項收緊: `Window` 與 `DailyRow` 的字串金額只接受固定兩位小數,防止分數寫法或不定小數位數穿過領域邊界；數值型別及負值的既有判定仍留給九條判斷。`test_fixed_two_decimal_amount_strings` 先翻紅後轉綠,領域子集 337 筆通過。寫下時(增量 2a)正式分析流程及 DSP 跨窗一致性還沒接;增量 2b 已接上(規則輪與讀取層的跨窗檢查,現況以程式碼為準,在那幾支檔的家 [[Systems/分析行程流程與檢查點]]〈Phase 14 增量 2b:正式規則照九條、規則輪分步蒐證〉)。[test:test_fixed_two_decimal_amount_strings]

2a 代碼審 r1（2026-09-26）:`_check_amount` 改用 [[任務流程領域模型]] 家 `_checks.is_amount_or_none`，跟分析端讀取白名單同一支判準(原本自寫一條只收 ASCII 的正規式，讀取層卻收 Unicode 數字，後續接線會讓讀取層放過領域會丟例外的值)；領域層不再匯入 `re`。[test:test_fixed_amount_strings_have_one_definition_everywhere]

## 增量 2b:提交時刻、截斷旗標與逐日讀取日(2026-09-26)

出處 [[Projects/RTB_Phase14正式規則照九條判斷_計劃]] 〈實作解讀〉增量 2b。
- `AdjustmentRow.committed_at`(帶時區):第 3 條另看過去調整的提交時刻(決策 now 前 3 天內 → 近期調整),補足被截斷的歷史;第 4 條的最新一筆加額要有提交時刻,而且到決策 now 為止 D+1..D+3 三個完整 UTC 日都已結束(`after_window_complete`:now 不早於 D+4 日 00:00 UTC)才採信後段轉換,否則證據不足;提交時刻晚於 now 當不合格列。缺提交時刻的過去調整列(舊呼叫端)判證據不足、不用 `days_ago` 補。
- `ChangeHistory.recent_flag`:DSP 歷史被截斷時由完整七日集合算的近期預算旗標;它以 DSP 讀取時刻切,窗只會比決策 now 的寬,當成近期調整是保守的一邊。
- `DailyTrend.read_at` 與原因 `day_boundary`:逐日讀取時刻跟決策 now 不同 UTC 日即證據不足([S1406]);評估案例不給讀取時刻。
- 評估轉接(`investigation_cases.rule_evidence`)同步帶上提交時刻與截斷旗標;72 筆逐筆格與答案不變(既有 72 筆回歸測試)。
- 防回歸:[test:test_past_adjustment_commit_time_is_judged_on_the_decision_clock]、[test:test_past_adjustment_without_or_after_the_decision_time_is_insufficient]、[test:test_truncated_history_recent_flag_counts_as_a_recent_change]、[test:test_daily_read_on_another_utc_day_is_insufficient]。

## 代碼審 r1:不合格查詢結果先擋(2026-09-26)

第 3 條之前先檢查四查詢是否「有效」:長窗負數或不自洽(點擊多於曝光、轉換多於點擊、1 天多於 7 天)、歷史或過去調整的提交時刻晚於決策 now、負數過去調整、不合格逐日列,一律無格證據不足(`INVALID_ROW_VALUE`),不讓另一個正數把不合格資料變成提案(外家 finder-1)。72 筆不受影響。出處 [[Projects/RTB_Phase14正式規則照九條判斷_計劃]]。[test:test_negative_or_inconsistent_longer_windows_are_insufficient]、[test:test_every_invalid_query_result_blocks_a_proposal_whatever_rule_would_hit]
