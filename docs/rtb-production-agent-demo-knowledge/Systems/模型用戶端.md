# 模型用戶端

模型呼叫的共用部分(計劃第 8 版〈模型用戶端〉〈花費帳與上限〉)。三個接入點經 `src/rtb/modelclient.py` 的
`call_model` 呼叫;即時後端是本機 Claude Code 的非互動模式,錄製重播不經後端。

## 各檔

模型用戶端拆成四支加一支協調(代碼審第 1 輪架構席:原本一檔裝四種職責,比照花費帳已示範的讀寫分檔):

- `src/rtb/modelcore.py`:共用詞彙——價目表與上限常數、系統時鐘(測試替換這裡)、請求與結果、九類例外與
  結算狀態、「送出一次呼叫」的後端介面、預留算法。
- `src/rtb/modelclaude.py`:Claude Code 後端,整個 rtb 唯一啟動子行程的模組。參數固定(非互動、JSON、
  固定思考強度、自己的系統提示、工具全關、不載 MCP、關斜線指令、安全模式、最少設定來源與空設定、不存對話、
  單次花費上限);使用者內容從標準輸入送;環境白名單五個鍵;每次新建的空暫存工作目錄、輸入輸出寫暫存檔;
  隔離方式照啟用紀錄(首選空暫存 HOME);新工作階段,清理順序是只等不領回、殺整組、確認沒有活的、最後領回。
  回應判定五步;即時啟動前的檢查(管理政策來源、啟用紀錄與 claude 版本、真 HOME 隔離時的記憶目錄)。
- `src/rtb/modelrecording.py`:錄製鍵、錄製檔讀寫(只新建不覆寫)、佔位符。
- `src/rtb/modelledger.py`:花費帳寫入——建表、預留(單一寫入交易讀已用、判上限)、結算、記 0 元的帳、
  人工核銷(只追加)。
- `src/rtb/modelclient.py`:協調——模式判定(`settings_from_env`)、結算規則、`call_model`,並把共用詞彙
  轉手給三個接入點(不轉手子行程的東西)。
- `src/rtb/modelledger_view.py`:花費帳唯讀開法、欄位清單、「一筆算進已用多少」的單一規則、三個封閉列舉。
  指標怎麼讀見 [[Systems/有界標籤的指標]]。
- `src/rtb/modelledger_writeoff.py`:人工核銷命令列(帳檔寫死家目錄那一本;依據寫本機紀錄)。
- `src/rtb/modelverify.py`:即時模式實測命令列。協調者在本機跑,全部通過才寫啟用紀錄;子行程經模型用戶端。
- `tests/conftest.py`:pytest 一啟動就改環境(HOME、PATH、開關),每支測試再給一個自己的家目錄;
  `tests/test_suite_isolation.py`:[S932]、[S935]。
- `tests/model/fakes.py`:行程內的假後端,以及假的 claude(/bin/sh 腳本,印固定 JSON、記下參數、環境、
  工作目錄、標準輸入);`tests/model/__init__.py` 空檔。
- `tests/model/test_modelclient.py`:[S900]–[S903]、[S907]、[S920]–[S922]、[S925]–[S927]、[S931]、
  [S941]、[S942];`tests/model/test_claude_backend.py`:[S904]–[S906]、[S936]、[S939]、[S940];
  `tests/model/test_writeoff.py`:[S923];`tests/model/test_verification.py`:實測命令列的判定與寫檔;
  `tests/test_spawn_boundary.py`:[S917](整個 rtb 只有模型用戶端能啟動子行程)。

## 代碼審第 1 輪補強(2026-09-24)

逐條解讀寫在計劃〈拆增量〉「增量 1 實作解讀」裡的「代碼審第 1 輪補強的解讀」;這裡只記落在哪:

- 子行程(`modelclaude.py`):等待途中被打斷照同一順序清理再往外丟,SIGTERM 在呼叫期間轉成 `CallTerminated`;
  登入檢查的時間從呼叫期限扣;子類型要是 success;成功形狀帶工具痕跡標工具使用;標準錯誤只進本機日誌;
  回報花費跟 token 數分開讀、快取寫入差額算 1 小時;管理政策來源加個人層 MDM 與 policyHelper(s)。
  防回歸:`tests/model/test_claude_process.py`。
- 錢(`modelcore.py`、`modelledger.py`、`modelclient.py`、`modelledger_view.py`):預留只讀一次鐘;預留列記主行程、
  開機識別與開機以來秒數,核銷時主行程還活著或兩種時鐘對不上就拒絕;荒謬值夾到上限判讀不懂、標超支;結算重試
  3 次、仍失敗印應入帳金額,狀態可以是「超支又未結算」;帳檔與啟用紀錄跟著帳號家目錄(`account_home`),不看 HOME。
  防回歸:`tests/model/test_ledger_hardening.py`。
- 錄製(`modelrecording.py`、`modelclient.py`):呼叫前獨佔建立佔住檔名、懸空符號連結算存在、寫不進去另立
  `RecordingWriteFailed`、存工具使用與無法可靠分類與結算狀態、載入時驗鍵與呼叫者與模型與型別、不存標準錯誤;
  花費帳或檔案系統的非模型例外包成暫時性、無法可靠分類。防回歸:`tests/model/test_recording_integrity.py`。
- 實測命令列(`modelverify.py`):記憶暗號、連不到的 API 位址當毒值加正面對照、輸出上限要撞頂證據、錯誤回應一律沒過、
  固定附加輸入要量得到且不超過 4000(新必過項目 `fixed_input_within_reserve`)。
- 測試隔離(`tests/conftest.py`):每支測試換掉帳號家目錄的讀法、自己的暫存目錄、管理政策來源指到空目錄;整套結束時
  連啟用紀錄一起比。子行程測試的環境一律從 os.environ 起頭(`tests/test_suite_isolation.py` 用語法樹掃)。
- 邊界:整個 rtb 只有模型用戶端各模組與實測命令列能碰 Claude Code 後端;DSP、執行端、領域層、維運的 ruff 設定
  禁匯入模型用戶端、Claude Code 後端與實測命令列(維運另禁核銷命令列);維運逐檔白名單的掃描範圍加上實測與核銷
  命令列(`tests/test_spawn_boundary.py`、[[Systems/追蹤檢視]] 的邊界測試)。

PITFALL: 假 claude 在孫行程起來之前就寫「已啟動」標記,中斷測試會在孫行程出生前殺整組、讀不到孫行程編號(看起來像測試壞了)。標記要寫在孫行程起來之後。出處:代碼審第 1 輪實作時。[test:test_an_interrupted_call_kills_the_whole_group]
