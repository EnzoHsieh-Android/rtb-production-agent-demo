# 執行迴圈

三支檔:`src/rtb/executor/execution.py`(處理一筆與 DSP 回應對照表)、`src/rtb/executor/dsp_client.py`(執行行程的 DSP 讀寫用戶端,經 [[Systems/共用行程基礎]] 的共用 HTTP 用戶端)、`src/rtb/executor/runner.py`(啟動程式與單一執行者鎖)。收件表與嘗試紀錄的儲存規則在 [[Systems/提案收件口]] 與 [[Systems/外部寫入嘗試紀錄]],簽發在 [[Systems/寫入能力憑證]]。

## 處理一筆的順序

1. 挑提案:依收到時間由舊到新,跳過同廣告已有未結案嘗試的。
2. 提案已過期就標已過期(不讀 DSP);否則重讀 DSP,讀不到(不含廣告不存在)就這一輪什麼都不寫。
3. 執行前檢查:廣告存在、仍在投放、版本等於提案觀察到的、簽發器願意簽;任一不過就在「仍待處理且內容雜湊沒變」的條件下標已擋下。
4. 同一個交易裡核對仍待處理、開始一筆、標已交給執行;鍵已存在就依既有那把鍵的狀態分流(失敗 → 擋下「同一操作先前已失敗」)。
5. 帶憑證與冪等鍵寫 DSP,回應經唯一一份對照表轉成嘗試狀態;憑證過期時重讀、重跑檢查、重讀時鐘重簽、同鍵重送一次。
6. 已提交待驗證就立刻做執行後驗證;之後的對帳是增量 4。

## 對帳的代碼審修正(2026-09-23)

- PITFALL: 對帳重送與憑證過期後的重簽,簽發都要用嘗試紀錄存下的鍵,不從提案重算;算法升版後重算會簽出另一把鍵,DSP 判範圍不符。出處:增量 4 代碼審外家席。防回歸:[test:test_a_resend_signs_the_stored_key_not_a_recomputed_one]、[test:test_a_resigned_capability_after_expiry_signs_the_stored_key]。
- PITFALL: 作廢呼叫的例外吞成「沒拿到回應」這段防護,要有測試真的讓它逾時才守得住(測試工具原本把作廢排除在故障注入之外)。出處:增量 4 代碼審資安席。防回歸:[test:test_a_void_call_that_times_out_comes_back_as_no_answer]。

- PITFALL: 讀 DSP 後的到期判斷要排在其他執行前檢查之前:讀取期間過期又同時不在投放時,要記「已過期」不是「不在投放」。防回歸:[test:test_an_expiry_during_the_read_wins_over_other_failed_checks]。
- PITFALL: 單一執行者鎖的檔名若含資料庫檔名,同目錄的硬連結會算出第二把鎖;鎖名只用裝置與 inode。防回歸:[test:test_the_runner_holds_a_single_instance_lock_and_recovers_before_ready](含硬連結)。
- PITFALL: 回應對照的測試若從程式自己的對照表產生案例,刪掉一列時案例跟著消失而假綠;預期值要手抄一份。防回歸:[test:test_every_dsp_answer_maps_to_the_documented_state_and_code]、[test:test_the_documented_answers_reach_every_row_of_the_response_table]。
- PITFALL: DSP 回的版本號若超過 64 位元整數上限,寫進資料庫時會丟非預期例外、繞過停機路徑;用戶端解析時超過上限就當讀不懂。防回歸:[test:test_an_oversized_version_from_the_dsp_is_treated_as_unreadable]。

## 對帳(Phase 3 增量 4)

- 每一輪先對帳、再處理一份新提案:結果不明與已提交待驗證的嘗試(轉人工不碰)各對帳一次,依最新一列寫入時間由舊到新;這一輪對帳只要有一次 DSP 呼叫失敗,就在這輪結束後休息一個間隔。防回歸:[test:test_each_round_reconciles_oldest_first_before_taking_a_new_proposal]、[test:test_a_round_with_a_failed_reconcile_call_sleeps]
- 結果不明:用冪等鍵查完整操作紀錄 → 查到就核對廣告、動作、新預算、預期版本都等於快照,再轉已提交待驗證並驗證(不符轉人工:冪等衝突);查不到就重讀廣告、重跑執行前檢查 → 通過就同鍵重送(寫結果整段沿用處理一筆那一段);廣告不存在直接失敗;業務上不過就先簽作廢、請 DSP 作廢,照作廢回應對照表判(已作廢 → 失敗 沒發生;已提交 → 走查到;簽不了作廢 → 轉人工 無法證明未發生)。
- WHY: 判失敗之前一定先作廢,因為「查不到」只代表那一刻還沒提交;作廢由 DSP 在寫入鎖下排隊,才是證明(見 [[Systems/Mock-DSP]])。出處:[[Projects/RTB_Phase3外部寫入安全_計劃]] 增量 4 設計審。
- PITFALL: 憑證過期後業務上不過時,只有這把鍵只送過一次(就是剛被拒的那一次)才能直接判失敗;送過多次(對帳重送、重啟恢復之後),更早的請求可能還在路上,要先作廢。防回歸:[test:test_an_expired_resend_after_earlier_sends_voids_before_failing]
- PITFALL: 「409 操作已作廢」要排在泛用的「409 版本衝突」之前:那一列不看錯誤代碼,放後面會被誤記成版本衝突。防回歸:[test:test_a_voided_key_answer_is_not_mistaken_for_a_version_conflict]
- 執行後驗證「目前版本大於寫入後版本」那一支改用完整操作紀錄核對內容,不只比寫入後版本。防回歸:[test:test_verification_after_a_later_write_checks_the_full_operation_record]
- 用戶端新增「查完整操作紀錄」與「作廢」;既有的「查寫入後版本」原樣保留。

## 佇列與租約圍籬(Phase 4 增量 1,2026-09-23)

- WHY: 處理一筆最前面是取件,收件表寫「處理中」並回一張收據;之後每一筆嘗試寫入都在同一個交易裡先核對收據並順手續租,嘗試到終點就在同一個交易裡確認(同一把租約管訊息與嘗試紀錄,Phase 0 的裁定)。出處:[[Projects/RTB_Phase4佇列與重新投遞_計劃]] 增量 1。
- RULE: 收據對不上是「放棄這把鍵」(LeaseLost),不是停機;只有嘗試紀錄自己的序號對不上才停機。多工作者下收據對不上是正常的租約競爭。[since:2026-09-23] [retire:多工作者改由佇列軟體的 fencing 負責時] 防回歸:[test:test_a_lost_lease_skips_the_key_without_halting]。
- RULE: 對帳每輪掃「未結案的嘗試(含嘗試中與轉人工)」與「嘗試已到終點、收件表卻還是處理中」;先原子接手租約(過期或擁有者是自己),接手後嘗試中先轉結果不明、轉人工只續租。[since:2026-09-23] [retire:同上] 防回歸:[test:test_reconciliation_only_takes_over_an_expired_or_own_lease]、[test:test_a_manual_resolution_is_acknowledged_by_the_next_reconciliation]、[test:test_reconciliation_recovers_an_in_flight_attempt_it_took_over]。
- PITFALL: 測試裡一次 DSP 呼叫把時鐘推過租約(60 秒),收據就會失效;要驗「跨過提案到期」得用 30 秒內到期的提案,不能再推兩小時。出處:增量 1 實作時既有測試翻紅。
