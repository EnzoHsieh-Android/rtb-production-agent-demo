# 宣稱驗證器

`tools/verify_claims.py` 讀 `claims/*.json` 五份證據清單,依序做格式、存在、依賴閉包與雜湊新舊、列舉覆蓋、故障注入,都沒擋才自己跑一次證據測試。`tools/claim_hashes.py` 是只印不寫的雜湊輔助。`tests/tools/test_verify_claims.py` 是它的測試。清單格式、每一步的規則與合約 [S800]–[S816] 以計劃為準,這裡只記程式看不出的脈絡。

## 用法

    python tools/verify_claims.py claims/

本機與 CI 同一條;CI 的 claims 工作跟 checks 平行。結束代碼 0 通過、1 擋下、2 無法判定(參數錯、清單讀不懂)。輸出開頭印驗證器與每份清單的 sha256 和目前提交編號,結果只印不存。

## 改了程式之後

範圍內任何一支檔(每份清單 20 到 33 支正式碼,依賴閉包算的)改了,CI 的 claims 工作就會擋「雜湊跟清單不一致」,直到有人重算清單裡的雜湊。先跑

    python -B -m tools.claim_hashes claims/

它只印出每份清單哪幾支檔的雜湊跟現況不一樣、正確值是多少,不寫任何檔(-B 是因為 python -m 會在它任何一行執行之前就把它編成 .pyc,程式裡攔不到;不加 -B 只會多出它自己那一個 .pyc);直接跑 python tools/claim_hashes.py 會印這條指令並回 2;清單照樣要人改。閉包少列的檔它不印,照驗證器擋下的原因補。重貼前要自己確認證據在語意上還成立——驗證器分不出「重看過」與「重貼」,輔助讓重貼更容易,這個天花板照舊歸審查員(見計劃〈實務隱患〉與 REVISIT)。

## 權限護欄那份清單怎麼挑的(增量 1 逐支選定)

這條沒有既有 ★INVARIANT★,從前掃列的測試檔逐支挑,每支對一個 policy 子句:
- 能力憑證:`tests/dsp/test_capability.py` 的沒有有效憑證被拒、別把金鑰簽的被拒、範圍任一欄不符被拒、時間窗外被拒——四支分別對「有效」「範圍對得上」;不挑接受邊界的正向測試,那是另一個方向。
- 簽發端:`test_the_executor_refuses_to_sign_outside_its_current_tenant_configuration`,租戶設定外不簽,對「租戶範圍」。
- 比例上限:`test_a_budget_increase_is_bounded_by_the_ratio_cap` 與 `test_a_ratio_block_writes_nothing`,前者邊界、後者擋下時沒寫。
- 決策過時:`test_a_stale_decision_is_blocked`。
- 廣告版本已變:`test_each_failed_precheck_blocks_the_proposal_without_a_write`,每一種執行前檢查失敗都不寫。
- 人工核可只對它簽的內容有效:核可範圍任一欄變了就失效、範圍到期雜湊階段變了就失效、只管自己那一階段,三支。
- 死信重放照樣重跑檢查:`test_a_replayed_proposal_goes_through_every_gate` 加 F6 端到端一支。
