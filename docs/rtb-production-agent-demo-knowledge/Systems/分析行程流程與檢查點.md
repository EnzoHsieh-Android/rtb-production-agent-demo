- 版本檢查、新鮮度、冪等的分工:版本檢查(執行端)防「根據過時現況做的決策覆蓋新值」;新鮮度(分析端)防「用過期證據做決策」;冪等(執行端與 DSP)防「同一個決策套用兩次」。三者互補、不能互相取代;這個階段多了一件:收件表清掉之後,冪等鍵是分析端查「有沒有寫進去」的鑰匙。

- **收件口回來的擋下原因只收固定清單**(版本已變、不允許、廣告不存在、廣告未啟用、同一操作先前已失敗);不在清單的當成回應讀不懂、這一輪沒有進展,不寫進只增不改的歷史表(2026-09-23 代碼審資安席:對方回什麼字串都原樣寫進稽核紀錄,是偽造稽核行與終端機逃逸的注入管道)。「不允許」是超過預算上限與廣告不屬於租戶合併後的泛稱:使用者 2026-09-23 裁定,分析行程不該能用重送試出預算上限與租戶歸屬。
