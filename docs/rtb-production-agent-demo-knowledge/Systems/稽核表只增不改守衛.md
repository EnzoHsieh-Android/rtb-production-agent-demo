# 稽核表只增不改守衛

本篇管 `tests/executor/test_audit_tables.py`(守衛測試與殺傷力配方)、`tests/executor/audit_guard.py`(稽核判定:哪幾張表受守護、哪些語句算改寫、補欄位規則、動態補欄位處數;Phase 8 死信守衛也從這裡匯入)與 `tests/executor/write_scan.py`(共用的原始碼掃描工具,只放兩種通用讀法:判寫入函式、拼回拆開的字串;維運套件邊界測試也用)。七張表的家:[[Systems/提案收件口]](停下紀錄、核可、核可使用、生命週期事件)、[[Systems/外部寫入嘗試紀錄]](嘗試紀錄、DSP 呼叫紀錄)、[[Systems/Mock-DSP]](操作紀錄)。

- 全庫掃 src/rtb 每一支,拼回字串時不算文件字串(說明裡提到改寫語句不是改寫)。
- 收件口的通用補欄位迴圈用 f-string 組表名,拼回來只剩占位;另外直接讀它的登記表,斷言登記在七張表之下的欄位定義都可為空、無預設值(今天只有嘗試紀錄[count:src/rtb/executor/inbox_store.py::_ADDED_COLUMNS=1]的欄位在裡面)。
- 七個表名[count:tests/executor/audit_guard.py::AUDITED=7]各要在某個建表語句裡出現剛好一次,拼錯守衛就守空了。
- 殺傷力配方:每張表至少一條,另外逐一涵蓋 UPDATE OR REPLACE、衝突時更新、DROP TABLE IF EXISTS、帶「資料庫名.」前綴、改名、刪欄、帶預設值或不可為空的補欄位;配方用拆開字串的寫法,不跟檢查用同一種字面。
- 防忘記,不防刻意繞過:用變數組表名、把關鍵字拆到兩個變數再串起來都繞得過;直接開資料庫改也擋不住。
- 代碼審第 1 輪(2026-09-24)四處補強:Phase 8 死信兩張表併進同一套判定(九張表共用;死信兩張表照原本一起掃文件字串、連可為空的補欄位都不准,只變嚴),防回歸 [test:test_the_dead_letter_guard_catches_each_rewrite];拼回字串認得字面模板 .format(參數) 與 字面 % 參數,參數全是常數就代入,含變數時保守回模板本身(模板有改寫語句與表名就算,寧可誤報),防回歸 [test:test_the_audit_guard_sees_through_format_and_percent];用變數組表名補欄位全庫只准一處(收件口的通用補欄位迴圈),新開第二處就紅、逼人接進同一個登記表,防回歸 [test:test_only_one_place_adds_columns_by_a_variable_table_name]。判定本身搬進共用掃描模組,兩支守衛測試都從那裡匯入(第 2 輪再搬到稽核守衛模組,見下一條)。
- 代碼審第 2 輪(2026-09-24):拼回字串改成遞迴時不壓空白、最外層整段壓一次(在空白處切開再用 + 串接,兩側各自壓空白會黏成一個字躲過比對,Phase 8 舊版也中招);.format 的具名引數與 % 右邊的字典都認,對不上常數或是變數就把佔位正規化成裸 {} 或 %s 再回模板。防回歸:[test:test_the_audit_guard_sees_through_split_and_named_placeholders]。稽核判定從共用掃描模組搬到稽核守衛模組,共用掃描模組只留通用讀法。
- 代碼審第 3 輪(2026-09-24):% 的字典與元組逐欄處理,解得出常數的佔位照樣代入、只有解不出的那一個正規化成 %s;.format 的格式規格帶精度時不照規格截字串,代入完整常數(截掉的可能正是表名,寧可誤報)。防回歸:[test:test_the_audit_guard_sees_through_split_and_named_placeholders];表名是常數、只有欄位定義是變數的補欄位不算第二處動態補欄位,防回歸:[test:test_only_one_place_adds_columns_by_a_variable_table_name]。
- 整合增量 1 後(2026-09-24):收件口的通用補欄位登記表多了 DSP 呼叫紀錄的內容雜湊欄(增量 1 代碼審第 2 輪,可為空、無預設值);守衛本來就逐欄驗整份登記表,只把「登記表裡受守護的表只有嘗試紀錄」那一行釘住的集合改成嘗試紀錄加 DSP 呼叫紀錄。
